## Goal

**Current behaviour:**

- T2 has installed the exact Storybook/Vitest stack and generated the Custom Elements Manifest. Initial story indexing fails on the required story-local decorated auto-accessor test host; the proposed D20 amendment isolates that fixture without changing the toolchain.
- The sidebar and welcome/content modals still use independent scaffold styles, unknown tokens and literal fallbacks. `tests/style-tokens.test.ts` exempts their files and `src/app.ts` through `KNOWN_DRIFT`. Nine entries in `tests/visual-parity/map.ts` still expect failure.
- `src/app.ts` mounts implemented data and target views, plus model/results placeholders. The shell has an inline style block; `css/style.css` loads thirteen mockup stylesheet copies. Internal feature styles live in Shadow DOM and must be preserved.
- `src/i18n.ts`, data ingestion, dataset cards, preview, transient data dialogs, column details and target selection already exist. The virtual table is being implemented separately. The dataset card lives in `src/components/app-dataset-card.ts`; this conflicts with the proposed feature placement.

- T1's moves, guards and approved D19 focus repair are complete. Automated three-browser checks and human Safari/VoiceOver verification are recorded below.
- Component conventions currently require Playwright acceptance tests and typed labels for presentational components, with an explicit i18n exception in the card spec. Story smoke tests must not silently replace those acceptance tests.

**Target behaviour:**

- `bun run storybook` previews the real shared primitives and shell components, with documented states, long labels and RTL examples. Editing their production style modules updates these previews.
- `bun run test:stories` runs story rendering, interactions and axe in Chromium, Firefox and WebKit. Playwright retains application acceptance, history, emulation and screenshot checks.
- Sidebar/workflow layout, typography, colours, borders, spacing and shadows match the named mockups at 1440×900, apart from the explicit deviations below. The welcome modal and shared dialog styling also match.
- The repaired shell has no token/parity exemptions. Screenshot baselines are established only after comparison against the mockups.
- The existing data and target screens, storage, routing semantics and reference journeys keep working. Storybook remains development-only.

**Why:** Human-authored CSS is the visual contract. Agents port those rules into Lit and prove the result, while Storybook supplies an editable workbench for the actual components.

- Production bundler, CSP, COOP/COEP, deployment, worker and service-worker changes.

**Constraints and invariants**

- Lit 3 standard decorators with `accessor`; never enable `experimentalDecorators`.
- Native HTML/CSS, Baseline Widely available, WCAG 2.2 AA, British English and Bun commands.
- Preserve element tags, URLs, event contracts, dataset identity and sidebar `aria-current` outcomes from conformance D14.
- Preserve the document scroll owner, router focus-request decisions, scroll-restoration algorithm, reserved-route underlay and close semantics. D19 repairs only execution of an existing focus request across component boundaries.
- No new visual choices beyond the listed translations. Port CSS declarations and preserve hooks wherever practical; do not substitute a generic component treatment.
- Tasks are sequential. Preserve concurrent/unrelated working-tree changes; no commits, branch changes or index staging are authorised by this plan.

- **Method contract:** required `AbortSignal`, no default; resolve after the focus attempt or a cancelled/disconnected/no-heading no-op. Return immediately for an already-aborted signal or disconnected instance before awaiting anything. Otherwise await the component's own `updateComplete`, then recheck `signal.aborted` and `isConnected` immediately before acting. Rendering errors remain errors; do not swallow them as successful focus. Query only the owning `renderRoot` for `.page-header > h1`. Never return internal nodes or query another component's shadow root. Methods emit no custom event, mutate no store and add no listener, timer or persistent state.
- **Nested preview:** after its own render, `AppDataView` checks cancellation/connection and its current subtree. In preview mode it delegates to its existing preview ref's `focusHeading(signal)` and awaits it. The preview waits for its own render and performs the same final checks. Selection focuses the data view's own heading. No focus operation waits for catalogue fetches, metadata, rows or `whenSettled()`. Loading, ready and error body updates retain the same heading node and do not request focus again.
- **Shell lifetime:** keep one module-private pending AbortController in `src/app.ts`. Abort/clear it at the start of each `renderAppShell()` call (route, reserved-route or data-mode changes); no pending operation survives replacement of its target. After rendering, consume `takeFocusRequest()` exactly once as now. Only a true request on a workflow route creates a new controller and invokes the active direct route element's method. Use an explicit local union of the four existing route-element types, not a new exported framework contract. The native `/results` placeholder retains a direct document-owned h1 focus with `preventScroll: true`. Clear the pending reference when its promise settles only if it still belongs to that request. No router, history, persister or scroll-restorer edits.
- **Decision table:** user workflow navigation and workflow-to-workflow popstate follow the existing router flag. Initial hydration/reload, duplicate current-link activation, ordinary store/resource renders, data-mode changes by themselves, opening/closing a reserved route, and reserved-to-workflow popstate generate no additional heading focus. A pending focus is cancelled when any later shell render occurs, even when it generates no new request. Native modal focus return remains browser-owned. Component removal causes a no-op after any await; reattachment works for a new explicit request.
- **Heading markup and styles:** add `tabindex="-1"` to the two data headings; preserve it on all other headings including Model Not Found. Never make a host or heading a normal Tab stop. New `src/styles/heading-focus.styles.ts` exports only TSDoc'd `headingFocusStyles: CSSResult`, containing `.page-header > h1:focus-visible { outline: 2px solid var(--focus-ring); outline-offset: 2px; }`. Adopt it in the document via the existing global initialiser and in the five owning components' style arrays. Five concrete shadow-root consumers authorise this small CSS extraction under COMPONENTS §3; no controller/base class/mixin is introduced. T3 composes the same CSSResult into `pageHeaderStyles` and removes its separate document adoption, retaining component adoption and every existing table/notification sheet. The Page Header stories in T3 cover this helper; feature-story migration remains outside scope.
- **Appearance/i18n:** no new copy, labels, roles, locale behaviour, tokens, motion or unfocused layout changes. Keep existing typography and draft-only surfaces.
