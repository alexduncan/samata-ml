## Goal

**Current behaviour:** `src/app.ts` L84–93 renders `/results` as an inline light-DOM placeholder (`h1` “Compare Results”, `section[data-testid="results-view"]`); it is absent from `WorkflowFocusView` (L51–55) and uses the document-adopted `pageHeaderStyles`. `tests/app-shell.e2e.ts` PH-AC-2 (L826–859) asserts the placeholder text (L855–857); FOCUS-AC-5 (L598–610) includes `/results`. `$canCompare` (`src/stores/predicates.ts` L28) is true at two or more trained models.

**Target behaviour:** `/results` renders a connected `app-results-view` that compares 2–8 trained models **evaluated on identical rows and partitions** (equal Phase 4 `partitionFingerprint`). It shows, without choosing a winner: a sortable table lens of balanced accuracy, macro-F1, MCC, accuracy, ROC-AUC, average precision, log loss, Brier, ECE, train–test gap, spread, error counts and protocol-appropriate timing against most-frequent and stratified baselines; paired outer-fold dot plots; per-class error bars; a relative confusion matrix for a chosen pair; a Bayesian ROPE probability bar for a chosen pair of cross-validated models; and an instance-agreement chart. Models evaluated on different rows are listed in other groups and never mixed.

**Why:** Comparison is where learners make choices; it must expose trade-offs, uncertainty and practical equivalence rather than a single-score leaderboard ([metrics-and-visuals note §2](../../notes/metrics-and-visuals.md); VISION §7, §10).

## Scope

**In scope**

- Comparison grouping by `partitionFingerprint`, default selection, and persisted `results.ui` state with one action and dataset/target ownership.
- An analysis worker and store that call `web-ml`'s Bayesian correlated t-test (WR-9).
- Presentational elements `app-comparison-controls`, `app-comparison-table`, `app-model-pair-picker`, `app-class-error-bars`, `app-confusion-delta`, `app-rope-bar`, `app-instance-agreement`; a `paired` property on Phase 4's `app-fold-strip`.
- Connected `app-results-view` replacing the `/results` placeholder, adopting `pageHeaderStyles`, with `focusHeading` and `whenSettled`.
- Update the existing draft `specification/mockups/04_compare-results.html`; stories; three-browser Playwright tests; reference journeys extended to two models.

**Out of scope**

- Normalised expected cost with a cost-ratio slider, subgroup fairness, superimposed ROC/PR curves, multi-model reliability diagrams, Pareto trade-off scatter and decision-boundary galleries — `specification/FUTURE.md` (user decision 2026-11-19 on optional items). FP and FN counts are in scope.
- Comparing models across different evaluation rows; regression models; any automatic "best model" label.
- Single-model views (Phase 4), model internals (Phase 6), tuning (Phase 7).

**Constraints and invariants**

- Only models with equal `partitionFingerprint` are compared; paired statistics use partitions with equal `index`.
- Every score, baseline and ROPE posterior comes from `web-ml` (WR-3, WR-4, WR-5, WR-9). Samata displays differences between reported values, reuses Phase 4 fold aggregation and counts stored per-row correctness for the instance-agreement display. Never fit, predict or recompute evaluation metrics or diagnostics in this phase.
- No automatic winner: no bold maxima, crowns or "best" text. Sorting is a user action.
- Strict TypeScript, Bun only, TSDoc, WCAG 2.2 AA, British English, `@nanostores/i18n`; charts follow Phase 4 D8 (figure, caption takeaway, data table).

#### A. State (`src/types/state.ts`, `src/stores/app.store.ts`, `src/stores/comparison-preferences.ts`, `src/stores/comparison.store.ts`)

```ts
export type ComparisonColumn =
	| 'balancedAccuracy'
	| 'macroF1'
	| 'mcc'
	| 'accuracy'
	| 'rocAuc'
	| 'averagePrecision'
	| 'logLoss'
	| 'brier'
	| 'ece'
	| 'gap'
	| 'sd'
	| 'iqr'

	| 'falseNegatives'

	target: string;
	epoch: number;
}

export interface ComparisonUi {
	fingerprint: string | null;
	selected: number[];
	sort: { column: ComparisonColumn; direction: 'ascending' | 'descending' } | null;
	pairA: number | null;
	pairB: number | null;
	ropeWidth: number;
	classFilter: number | null;

```

- `PersistedAppState.results` is `{ owner: ComparisonOwner | null; ui: ComparisonUi }`. `setComparisonUi(expectedOwner: ComparisonOwner, patch: Partial<ComparisonUi>): void` compares the owner captured by the rendered view or queued reconciliation with the current owner. Ignore the action if the context is absent or differs. Within a matching context, patch the currently owned preferences or start from defaults, then save with the current owner in one ordinary state update. Defaults: `fingerprint: null`, `selected: []`, `sort: null`, `pairA: null`, `pairB: null`, `ropeWidth: 0.01`, `classFilter: null`. The fingerprint accepts 64 lowercase hex characters or null. Validate sort column/direction against the declared union and retain only unique positive integer model numbers, sorted and capped at eight. A valid width is a finite number on the permitted 0.001 steps. The filter accepts non-negative integers or null and becomes null when outside the active axis or when that axis has at most 20 classes. The persisted `null` fingerprint means defaults have not been chosen; a matching fingerprint with an empty selection represents a deliberate selection.
- Add a top-level `comparisonContextEpoch: number` to normalised `PersistedAppState` and to the protected snapshot `Pick`. The current owner is the tuple of `dataset.id`, target column and epoch when both dataset and target exist. The default epoch is 0 for app v1 state and legacy v1 checkpoint payloads. Validate explicit epochs as non-negative safe integers. An invalid app epoch resets the epoch and clears preferences during decode; a malformed explicit pending epoch uses existing invalid-checkpoint handling. Keep the wire schema versions. An absent, malformed or mismatching `results.owner` decodes to the unowned defaults. Valid same-context preferences survive reload, ordinary merges, model creation, training, retraining and individual deletion, with existing selection pruning.
- Advance the epoch and clear `results` together in the dataset replacement/clear, actual target change and confirmed full model-discard reducers, including recovery that invalidates a missing dataset or target. Keep the epoch on refused/same-target updates and on the dataset refresh path that retains the protected domain. Use the same transition rule for browser protected operations and direct fixture reducers. Clear invalid preference ownership when recovery finds an already absent dataset or target. Carry the epoch through both `training-service.ts` and `reconciler.ts` snapshot extractors and `training-domain.ts` pending checkpoint decoder. Replay uses the captured epoch from the pending operation so publication retries never advance it twice.
- Share ownership checks in `comparison-preferences.ts`. In `persister.ts`, guard `results` explicitly on pending publication/replay, newer-snapshot publication, ordinary merges, the local-ordinary overlay and direct ordinary writes. First determine the final protected domain. Validate each candidate against its own snapshot and that destination domain before copying it. An ordinary preference write merges over authoritative storage preferences only when the local `results` differs from the writer’s last acknowledged base and is still owned by the final context. Protected publication writes the valid authoritative preferences to disk. Its in-memory overlay may retain a valid dirty local edit for a subsequent ordinary write while keeping the saved snapshot as the acknowledgement baseline. The direct fixture writer has no cross-tab merge and still validates its candidate before serialising. With no applicable local edit, preserve the valid authoritative `results`. When neither candidate qualifies, use unowned defaults. An owned empty selection is an edit. Exclude `results` from the generic ordinary preference overlay. Revalidate ownership before storage writes and acknowledged in-memory publication, including the submitted-draft and recovered-snapshot writers, and in both startup reconciliation paths. Prune model numbers against the destination models after context validation. A stored fingerprint is never evidence of ownership.
- `$comparison` derives from `$appState` and `$modelResults`. It exposes groups, the effective active group and selection, and trained models with unavailable data, with view reasons `loading` (including idle), `legacy`, `lost` or `error`. `loadComparisonResults()` calls Phase 4 `loadModelResults(num)` for all trained models; retries call `retryModelResults(num)`. Legacy trained results remain trained and use the Phase 4 retraining explanation. Stale run entries are ignored. A new dataset or model run invalidates prior analysis even if a model number is reused.
- Pure `src/features/results/comparison-model.ts` owns group validation and view projections. Table model values use `pooled.test`; MCC, ROC-AUC, average precision, log loss and Brier preserve upstream availability tags. ECE uses `curves.calibration?.expectedCalibrationError` and reports missing calibration as unavailable. SD and IQR use `foldSummary` over held-out balanced accuracy, with no spread for One-Shot. Gap is the mean of partition-by-partition train minus test balanced accuracy, as in Phase 4 §D. FP/FN use the off-diagonal pooled counts relative to `positiveClassIndex`; total errors use sample count minus the diagonal total. Use the One-Shot partition's `durationMs` as fit time and label the sum of the CV partition durations “Fit + score across folds”. Baseline cells for spread, gap, ECE and timing are unavailable; only show FP/FN in binary group tables. Keep the two baseline rows in most-frequent, stratified order. Class-error rows read the pooled true-class support and recall; use `1 - recall` for a class with support and show “Unavailable” for an empty class.
- Pure comparison view types: model option `{ num: number; label: string }`; group option `{ fingerprint: string; protocol: StoredEvaluation['protocol']['kind']; modelCount: number; disabled: boolean; reason: 'single-model' | 'inconsistent' | null; text: string }`; raw metric cell `ComparisonMetricCell = { value: number | null; unavailableReason?: MetricUnavailableReason }`; raw model/baseline table row `{ id: string; label: string; kind: 'model' | 'baseline'; metrics: Readonly<Partial<Record<ComparisonColumn, ComparisonMetricCell>>> }`. The presentational table receives `ComparisonCellView = ComparisonMetricCell & { text: string }` and `ComparisonRowView = { id: string; label: string; kind: 'model' | 'baseline'; metrics: Readonly<Partial<Record<ComparisonColumn, ComparisonCellView>>> }`. The connected view constructs each group's complete localised `text` using its protocol, model count and, when disabled, its `reason`; use separate plural-aware messages for One-Shot and cross-validation and append a localised singleton or inconsistent-data reason in the same message. The option value is the fingerprint, never the displayed text. Keep a raw numeric value through sorting, and have the connected view attach localised `text` to every provided cell, including unavailable values, before passing it to the table. A column is `{ id: ComparisonColumn; label: string; lowerIsBetter: boolean }`; the connected view owns the formatter for each column. A sort on a column hidden in the active comparison renders in model-number order with no active sort indicator. Class-error rows have class index, class label and one item per selected model with model number, label and nullable error rate. The confusion view carries both model labels, the full ordered class labels and signed row-major counts, the displayed true-class indices, and the nullable largest off-diagonal difference (true index, predicted index and signed count). The agreement view carries `counts: readonly number[]` ordered from zero to M models correct.

#### B. Worker protocol and analysis lifetime

```ts
export interface RopeRequest {
	id: number;
	type: 'rope';
	scoresA: number[];
	scoresB: number[];
	rope: number;
	testFraction: number;
}

export type RopeReply =
	| { id: number; type: 'rope-result'; result: RopeView }
	| { id: number; type: 'rope-error'; reason: 'invalid-input' | 'analysis-failed' };

export interface RopeView {
	probabilityLower: number;
	probabilityEquivalent: number;
	probabilityHigher: number;
}
```

- The installed root declaration takes two `ArrayLike<number>` values and options `{ rope, testFraction }`. Score arrays must be equally long, finite and have at least two entries. It returns the three probabilities above plus `meanDifference`, `scale` and `degreesOfFreedom`. The worker copies only the probabilities. `scripts/build-assets.ts` builds `/analysis.worker.js` as an ESM entry and injects the existing `WEB_ML_RUNTIME_URL`. The deployed graph root is `/web-ml/0.2.0-<graphDigest>/index.js`. No change is needed to build-model-assets or the training worker. For this higher-is-better outcome, `probabilityLower` is B better, `probabilityEquivalent` is practical equivalence and `probabilityHigher` is A better. Test both orders against the library on asymmetric fixtures.
- Share the types and guards in `analysis-protocol.ts`. Require a positive safe request ID, supported type, paired finite score arrays within 2–10 entries, width within UI bounds and a finite `testFraction` strictly between 0 and 1. Ignore unidentifiable malformed messages. Reply with the captured ID for recognised invalid requests, library failures and successful calls. Reject malformed success replies, including a probability outside [0, 1] or a sum differing from 1 by more than `1e-9`.
- `analysis-client.ts` lazily creates a same-origin module worker using the injected asset URL; the worker imports the same vendored root URL as training. The client exposes `requestRope(input, signal): Promise<RopeView>` with monotonic IDs, settles each request once, and rejects/cleans pending requests on abort, worker failure or disposal. Aborting detaches the caller; it need not interrupt an already-running synchronous library call. Ignore late replies and clear the failed worker so Retry can start a new one.
- `$ropeAnalysis` exposes the current key and discriminated `idle | loading | ready | error | unavailable` resource, with a result only on `ready`. Its key is the JSON tuple of runtime revision, partition fingerprint, full run identities A and B in order, and committed width. Reuse the current terminal success on the same key. Cancel the debounce and invalidate the request on key change, dataset/route departure or transition to an ineligible pair. Retry uses the same current valid inputs and a new request ID. Runtime errors become localised status text. Never send model objects, fitted artefacts or row data to the analysis worker.
