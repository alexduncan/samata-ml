## Goal

**Current behaviour:** In `samata-ml`, automated WCAG compliance checks (`tests/a11y.e2e.ts`, inline `AxeBuilder` calls across 15 functional E2E suites, and `.storybook/preview.ts` `a11y: { test: 'error' }`) and mockup visual-parity assertions (`tests/visual-parity.e2e.ts` and the `<main>` padding check in `PH-AC-2` at `tests/app-shell.e2e.ts#L1201-L1239`) run as hard-failing errors in the blocking CI pipeline (`.github/workflows/ci.yml`). Because the project is in beta, 13 tests remain suppressed in `tests/known-failures.ts` (10 visual parity, 1 duplicated `<main>` padding check `PH-AC-2`, 1 Chromium timing flake `WML-P2-ROUTE-2`, and 1 Firefox `AxeBuilder` crash `TRAIN-REMOTE-RECOVERY`), while additional browser E2E flakes (`WML-P4-UI-7`, `FOCUS-AC-5`, `TERM-AC-1`, `SNC-15` on Linux WebKit, and `tests/storage-worker.e2e.ts` racing `/data` bootstrap with opaque `[object Object]` rejections), hardcoded sample counts (`11` in `DATA-FLOW-2` and `DATA-UP-2`), interim Firefox `AxeBuilder` guards, and a spurious `AggregateError` GitHub Actions annotation emitted during `bun test` (`tests/setup.ts` exposing `happy-dom`'s `XMLHttpRequest` onto `globalThis` when `tests/audit-mockups.test.ts` imports `@playwright/test`) still weaken CI signal.

**Target behaviour:** Blocking CI checks (`verify` and 3-browser `e2e`, gating `deploy`) enforce **functional robustness in expected use cases** — core user workflows, data ingestion, persistence, worker training, routing, CSP/console hygiene, token hygiene, and Storybook interaction tests — with **zero** entries in `KNOWN_FAILURES`. Automated WCAG audits and mockup visual-parity checks remain active as **non-blocking warnings** during beta: Storybook reports `@storybook/addon-a11y` findings as `'todo'` warnings, inline `AxeBuilder` scans in functional E2E tests emit Chromium-only warning annotations without failing functional tests (and skip Firefox/WebKit in beta mode), and a dedicated non-blocking Chromium `advisory` CI job (`continue-on-error: true`, outside `deploy.needs`) runs `tests/visual-parity.e2e.ts` and `tests/a11y.e2e.ts` so visual and WCAG drift stays visible without blocking beta deploys. A single severity value (`SAMATA_ADVISORY_CHECKS=error`) restores strict V1 error enforcement across all three layers. Locally it is an environment variable; CI propagates the GitHub repository variable of the same name through workflow-level `env`. In strict mode the blocking E2E matrix includes the dedicated WCAG and visual suites, so their failures gate deployment through `e2e` even though the separate advisory job remains non-blocking.

**Content checks:** Functional E2E uses controlled content responses and stable selectors for reserved dialogs, Help entry points and Welcome. A shared compiler check validates authored Markdown during development, before commit and in blocking CI.

**Why:** Shipping a reliable beta requires high-signal tests that catch real user-facing errors without red-lighting CI over cosmetic mockup iterations, aspirational WCAG gaps, hardcoded inventory counts, or timing races in test harnesses.

### Interfaces and behaviour

#### 1. `tests/helpers/advisory-a11y.ts`

Runtime-neutral helper usable from both Playwright E2E suites (`playwright test`) and Bun unit tests (`bun test`). Uses **type-only** `@playwright/test` imports (`import type { TestInfo }`) with zero runtime imports of `@playwright/test` or `bun:test`.

```ts
import type { TestInfo } from '@playwright/test';

/** Severity mode for beta-advisory accessibility checks. */
export type AdvisoryCheckMode = 'warn' | 'error';

/**
 * Resolves the active advisory check mode from `SAMATA_ADVISORY_CHECKS`.
 * Defaults to `'warn'` during beta; returns `'error'` only when set to `'error'`.
 */
export function advisoryCheckMode(
	env: Record<string, string | undefined> = process.env
): AdvisoryCheckMode;

/**
 * Executes an accessibility scan callback with tier-aware severity handling.
 * - In `'warn'` mode on non-Chromium browsers (`testInfo.project.name !== 'chromium'`):
 *   skips the scan and adds an `'a11y-skipped'` annotation without failing.
 * - In `'warn'` mode on Chromium: runs `scan`; if violations are returned or thrown,
 *   records an `'a11y-warning'` annotation and logs a structured warning without failing.
 * - In `'error'` mode (any browser): runs `scan`, rethrows scan errors, and throws a standard
 *   `Error` listing rule IDs and node counts when `violations.length > 0`.
 */
export async function runAdvisoryAxe<T extends { id: string; nodes?: unknown[] }>(
	testInfo: Pick<TestInfo, 'project' | 'annotations'>,
	scan: () => Promise<readonly T[]>,
	options?: {
		readonly label?: string;
		readonly mode?: AdvisoryCheckMode;
		readonly warn?: (message: string) => void;
	}
): Promise<void>;
```

- `label` defaults to `'a11y'`. Violation summaries format each rule as `${v.id} (${v.nodes.length})` when `Array.isArray(v.nodes)` (otherwise `v.id`), joined by `', '`.
- When `mode === 'warn'` and `testInfo.project.name !== 'chromium'`: skips `scan()` and appends `{ type: 'a11y-skipped', description: `${label}: skipped advisory WCAG scan on ${testInfo.project.name} (beta Chromium-only)` }` to `testInfo.annotations`.
- When `mode === 'warn'` on Chromium and `scan()` returns a non-empty violation list: formats `${label}: ${violations.length} advisory WCAG finding(s) (${ids})`, appends `{ type: 'a11y-warning', description }` to `testInfo.annotations`, and calls `warn(description)` (defaulting to `console.warn`).
- When `mode === 'warn'` on Chromium and `scan()` throws (for example a transient axe runtime error): formats `${label}: advisory WCAG scan failed (${message})`, appends `{ type: 'a11y-warning', description }`, and calls `warn(description)` without failing the functional test.
- When `mode === 'error'` (any browser): rethrows any error thrown by `scan()`, and when `violations.length > 0` throws `new Error(`${label}: ${violations.length} WCAG finding(s) (${ids})`)` — keeping the module free of runner-specific `expect` imports so Playwright tests fail cleanly and `bun test` can assert rejections with `expect(...).rejects.toThrow(...)`.
