## Goal

**Current behaviour:** `package.json` has no `"version"` field, no `wrangler` dev dependency and no release, lint or deployment scripts. `wrangler.jsonc` uses the legacy worker name `"web-ml-app"` (`specification/README.md` Known gap 10), sets `"preview_urls": false` and routes to the placeholder `app.example.com`. `scripts/build-assets.ts` runs one JavaScript `Bun.build` (L51–L66) over `src/app.ts` and three workers (`storage.worker.ts`, `training.worker.ts`, `src/features/results/analysis.worker.ts`; L41–L46) and revs only `app.js` and `style.css` (L151–L152). Workers are spawned at the fixed URLs `/storage.worker.js` (`src/features/data/ingestion/storage-client.ts` L182), `/training.worker.js` (`src/features/models/training/training-service.ts` L298) and `/analysis.worker.js` (`src/features/results/analysis-client.ts` L17). Content and dataset `index.json` manifests are fetched without a version. `buildProductionBundle` inlines the whole stylesheet into `index.html` next to its `<link>` (`scripts/build-assets.ts` L153–L159; Known gap 3). `public/_headers` sets no `Cache-Control`, and `public/robots.txt` is missing. The local servers apply only hard-coded COOP/COEP/CORP and never read `_headers`. The storage client has no worker `error` or `messageerror` listener. Nothing tells an open tab that a deployment replaced its workers. There is no beta telemetry, no TSDoc lint (Known gap 7; `eslint-plugin-tsdoc` is installed but unused), no `SECURITY.md` and no `.github/workflows/`.

**Target behaviour:** `samata-ml` is versioned under SemVer from `0.1.0-beta.1`, with `CHANGELOG.md`, `bun run version:release` and build-time `APP_VERSION`. `wrangler.jsonc` names the Worker `samata-ml`, enables Version URLs and serves `beta.samata.ml`, with pinned `wrangler` scripts `deploy` and `deploy:dry-run`. Production JavaScript, CSS and workers live under content-hashed `/bundles/` names with immutable caching, while the shell, manifests, `robots.txt` and `release.json` revalidate. The local `--dist` server applies the emitted `_headers` with Cloudflare's matching rules. When a worker fails to start or crashes in a tab whose deployed build has changed, the shell offers a **Reload** notice. The beta serves deny-all crawler directives until an explicit V1 opening. Umami Cloud receives cookieless, allowlisted pageviews and fixed-name events, including fixed exception events, only on `beta.samata.ml` after **Get Started**, which is a condition of using the beta. A TSDoc lint (`bun run lint`), `SECURITY.md` and a self-contained GitHub Actions workflow verify pull requests and deploy pushes to `main`, skipping only tracked known failures in the browser projects where they fail.

**Why:** A reliable beta release and patch pipeline with automatic Cloudflare deployment, no stale-cache protocol mismatches, enforced TSDoc and security hygiene, and minimal beta usage and reliability data while learner datasets and models stay in the browser.

## Scope

**In scope**

- SemVer versioning, `CHANGELOG.md`, `scripts/release.ts`, a shared build-constants module and its test and Storybook equivalents.
- Cloudflare configuration: pinned `wrangler`, the `samata-ml` name (Known gap 10), Version URLs, the `beta.samata.ml` Custom Domain and the deploy scripts.
- Content-hashed `/bundles/` output for the app, stylesheet, three workers and chunks; versioned manifest fetches; `release.json`; no CSS inlining (Known gap 3); `Cache-Control`, crawler headers and `robots.txt`; a Cloudflare-compatible `_headers` parser used by the build tests and the local `--dist` server.
- Beta crawler exclusion with an explicit V1 opening procedure.
- Stale-release detection through a worker-failure signal plus a `release.json` probe, with a shell notice.
- Umami Cloud analytics and fixed exception events on the beta host, the welcome disclosure with a privacy-policy link, acceptance on **Get Started**, and privacy-policy copy.
- A TSDoc syntax lint and `SECURITY.md`.
- A self-contained `.github/workflows/ci.yml` (maintainer decision 2026-11-23), replacing the earlier dependency on an `agent-workflow` template, and a tracked per-project known-failure list for E2E (maintainer decision 2026-11-23).

**Out of scope**

- Modifying `../web-ml`, `../agent-workflow` or the vendored tarball.
- Adopting a shared `agent-workflow` CI template, branch rulesets, commit-grammar, link or spec-drift CI checks. A later plan may migrate this workflow once that template exists.
- Running `bun run plans:check` in CI: its scripts live under `$HOME/.agents/skills/`, outside this repository. It remains a local gate.
- The offline Service Worker (Known gap 6), fixing or re-baselining the inherited E2E failures (model-builder, visual parity, `PH-AC-2`) or the feature contrast items in `specification/HUMAN.md` §1.
- Cookies, session replay, identity calls, performance capture, optional analytics settings, telemetry in V1 and history rewriting.

**Constraints and invariants**

- **Local data:** Datasets, filenames, row counts, column names, cell values, target names, error messages, stacks and model artefacts never leave the browser. Umami receives only allowlisted fields, canonical route paths and fixed event names, with no event properties.
- **Gates:** Telemetry needs all three of the beta build flag, `location.hostname === 'beta.samata.ml'` and recorded acceptance.
- **Backward-compatible state:** Keep `STORAGE_VERSION = 1` and existing learner data. Only **Get Started** on the beta notice records `onboarding.betaTelemetryAccepted: true`.
- **CSP and isolation:** Keep COOP `same-origin`, COEP `require-corp`, CORP `same-origin` and every existing CSP source, including sources added by `sample-dataset-publication` (Palmer Penguins and Hugging Face CSV sources in `connect-src`). The beta artefact inserts exactly `https://cloud.umami.is/script.js` into `script-src` and `https://gateway.umami.is` into `connect-src` by token insertion into the existing directives, never by replacing the line. Every emitted `_headers` line stays at or below 2,000 characters and the file at or below 100 rules (Cloudflare limits).
- **Build constants:** Code reachable from a worker entrypoint reads only `DEBUG`, `APP_VERSION`, `WEB_ML_RUNTIME_URL` and `WEB_ML_RUNTIME_REVISION`, the constants the worker pass defines. Source code reads build constants as bare identifiers. Every runtime supplies them: `Bun.build` `define`, the `bun test` preload and the Storybook/Vitest `define`. No `typeof` fallbacks are added.
- **Repository conventions:** Obey `tests/repository-conventions.test.ts` (CONV-1–4: kebab-case names, allowed suffixes, no Lit imports under `src/common/`). Bun only, British English, TSDoc on exports, Prettier on changed files.

### Umami Cloud contract

The maintainer supplied this website configuration for `beta.samata.ml`:

```html
<script
	defer
	src="https://cloud.umami.is/script.js"
	data-website-id="e13bc119-a1c5-448e-b1ab-0203b71df348"></script>
```

The website ID is public browser configuration and needs no API key. The hosted script changes in place, so the CSP uses its exact URL rather than a digest. `crossorigin="anonymous"` satisfies COEP through CORS, and `referrerpolicy="no-referrer"` protects the script request.

#### A. Versioning, build constants and `scripts/release.ts`

Package binaries resolve through `bun run`, so no `bunx` is needed.

- `src/types/env.d.ts` declares `DEBUG: boolean`, `APP_VERSION: string`, `BUILD_ID: string`, `BETA_TELEMETRY_ENABLED: boolean`, `STORAGE_WORKER_URL: string`, `TRAINING_WORKER_URL: string`, `ANALYSIS_WORKER_URL: string`, `CONTENT_INDEX_VERSION: string`, `DATASETS_INDEX_VERSION: string`, `WEB_ML_RUNTIME_URL: string` and `WEB_ML_RUNTIME_REVISION: string`, each with TSDoc.
- `scripts/build-constants.ts` exports `interface BuildConstants` (the fields above except `WEB_ML_*`, which stay with the model-asset build), `toDefine(constants: BuildConstants): Record<string, string>` (JSON-stringifies every value) and `TEST_BUILD_CONSTANTS: BuildConstants` = `{ DEBUG: false, APP_VERSION: '0.0.0-test', BUILD_ID: 'test', BETA_TELEMETRY_ENABLED: false, STORAGE_WORKER_URL: '/storage.worker.js', TRAINING_WORKER_URL: '/training.worker.js', ANALYSIS_WORKER_URL: '/analysis.worker.js', CONTENT_INDEX_VERSION: '', DATASETS_INDEX_VERSION: '' }`. `tests/setup.ts` runs `Object.assign(globalThis, TEST_BUILD_CONSTANTS)` and assigns `WEB_ML_RUNTIME_URL = '/web-ml/test/index.js'` and `WEB_ML_RUNTIME_REVISION = 'test'` only when they are undefined. `.storybook/main.ts` `viteFinal` adds `define: { ...config.define, ...toDefine(TEST_BUILD_CONSTANTS) }`, which covers `bun run storybook`, `storybook:build` and `test:stories` (Vitest loads the same `configDir`).
- `bumpSemVer(version, bump, preid = 'beta')` accepts `MAJOR.MINOR.PATCH` or `MAJOR.MINOR.PATCH-beta.N` (non-negative integers without leading zeros, `N ≥ 1`) and rejects build metadata or other prerelease identifiers:

| From           | `prerelease`   | `patch` | `minor` | `major` |
| -------------- | -------------- | ------- | ------- | ------- |
| `0.1.0-beta.1` | `0.1.0-beta.2` | `0.1.0` | `0.1.0` | `1.0.0` |
| `0.1.2-beta.3` | `0.1.2-beta.4` | `0.1.2` | `0.2.0` | `1.0.0` |
| `1.0.0-beta.2` | `1.0.0-beta.3` | `1.0.0` | `1.0.0` | `1.0.0` |
| `0.1.0`        | `0.1.1-beta.1` | `0.1.1` | `0.2.0` | `1.0.0` |
| `1.2.3`        | `1.2.4-beta.1` | `1.2.4` | `1.3.0` | `2.0.0` |

A prerelease `minor` or `major` drops the prerelease when the lower components are already zero, as `npm version` does.

- `parseSemVer(version)` returns `{ major, minor, patch, prerelease: number | null }` or throws `Error` naming the input. `formatChangelogEntry(version, isoDate, notes)` returns `## [<version>] - <YYYY-MM-DD>` followed by one `- ` line per note (or `- No notable changes.`).
- CLI `bun run version:release <prerelease|patch|minor|major> [--dry-run]`: validate the argument; read the version; compute the next version. `--dry-run` prints the current version, next version and changelog section, then exits 0 without writing. Without it: require a clean `git status --porcelain`; run `bun run lint`, `bun run check`, `bun run build` and `bun run plans:check`; move `## [Unreleased]` notes into the new section; write `package.json` and `CHANGELOG.md`; run `bun run format package.json CHANGELOG.md`; print `git add package.json CHANGELOG.md`, `git commit -m "chore: release v<version>"` and `git tag -a v<version> -m "Release v<version>"` for the maintainer. It never runs Git writes.

#### B. Hashed build, manifests, `release.json`, headers and crawler policy

- `buildProductionBundle(options: ProductionBuildOptions = {})`, where `ProductionBuildOptions` is `{ outDir?: string; version?: string; betaTelemetry?: boolean; crawlerPolicy?: 'closed' | 'public'; workerEntrypoints?: Partial<Record<'storage' | 'training' | 'analysis', string>> }`.
    - Defaults: `outDir` is `DIST_DIR`; `version` comes from `package.json`; `betaTelemetry` is false; `crawlerPolicy` is `'closed'`; `workerEntrypoints` are the source paths. `buildDevBundle` takes the same `outDir`, `version` and `crawlerPolicy` options.
    - `version`, `workerEntrypoints` and a non-default `outDir` exist for tests and are documented as such in TSDoc. `version` must pass `parseSemVer`.
    - `scripts/build.ts` maps CLI input onto these options: `--out-dir <relative path>` (resolved under the repository root; it rejects absolute paths, `..` and paths outside `out/`, `dist/` or `dev/`), `BETA_TELEMETRY_ENABLED=true` to `betaTelemetry`, and `SAMATA_CRAWLER_POLICY` (`closed` or `public`; any other value exits non-zero) to `crawlerPolicy`.
- Build order (both modes unless stated):
    1. Existing model assets, content and datasets.
    2. `CONTENT_INDEX_VERSION` = first 12 hex of SHA-256 over the concatenated bytes of `content/<locale>/<domain>/index.json` for each locale in `src/config/locales.ts` order and each domain in `DOMAINS` order (`pages`, `models`, `glossary`). `DATASETS_INDEX_VERSION` = first 12 hex of SHA-256 of `datasets/index.json`.
    3. Worker pass: one `Bun.build` over storage, training and analysis workers (plus the probe when enabled) with `splitting: false`, the existing `external` and `define` of `DEBUG`, `APP_VERSION`, `WEB_ML_RUNTIME_URL` and `WEB_ML_RUNTIME_REVISION`. Production outputs go to `<outDir>/bundles/`, and the three workers are revved with `writeRevvedFile`. When enabled, the probe is built in a separate `Bun.build` to `<outDir>/runtime.worker.js` in both modes and never revved. Dev outputs stay at the root names.
    4. `BUILD_ID` = first 12 hex of SHA-256 over `APP_VERSION`, `WEB_ML_RUNTIME_REVISION`, the SHA-256 of each worker's bytes (storage, training, analysis order), `CONTENT_INDEX_VERSION` and `DATASETS_INDEX_VERSION`, joined with LF.
    5. App pass: `src/app.ts`, `splitting: true`, `naming: { entry: '[name].[ext]', chunk: 'chunks/[name]-[hash].[ext]' }`, `define` from `toDefine` plus the two `WEB_ML_*` values. Production output goes to `<outDir>/bundles/`, and `app.js` is revved.
    6. CSS pass: production output goes to `<outDir>/bundles/style.css`, then is revved.
    7. `release.json` = `{"version":"<APP_VERSION>","build":"<BUILD_ID>","workers":{"storage":"<url>","training":"<url>","analysis":"<url>"}}` plus LF.
    8. Generate `_headers` and `robots.txt` (below) from `public/`.
    9. Production `index.html` via `transformIndexHtml`: links `/bundles/style.<hash>.css` and `/bundles/app.<hash>.js`, adds `<meta name="app-version" content="<APP_VERSION>" />`, and no `<style data-inline-build="true">`.
- `ProductionBuildResult` = `{ jsFile, cssFile, storageWorkerFile, trainingWorkerFile, analysisWorkerFile, appVersion, buildId }`, with files as root-absolute URLs.
- Runtime: `storage-client.ts` L182 uses `new Worker(STORAGE_WORKER_URL, …)`, `training-service.ts` L298 uses `TRAINING_WORKER_URL`, and `analysis-client.ts` L17 uses `ANALYSIS_WORKER_URL`. `content-loader.ts` (URL built at L113) and `sample-datasets.ts` L12 append `?v=<version>` when the version is non-empty.
- `BETA_TELEMETRY_ENABLED` is true only for a production build with `betaTelemetry: true` and a `-beta.N` version.
- Emitted `_headers`, generated by `scripts/release-headers.ts` `renderHeaders(baseline: string, options: { telemetry: boolean; crawler: 'closed' | 'public' }): string`:
    - The `/*` rule keeps every baseline line and adds `Cache-Control: public, max-age=0, must-revalidate`. Closed adds `X-Robots-Tag: noindex, nofollow, nosnippet`. Telemetry inserts the two Umami tokens after `'self'` in `script-src` and at the end of `connect-src`.
    - Baseline `/content/*` and `/datasets/*` rules stay unchanged.
    - Appended after them: `/bundles/*` and `/web-ml/*`, each with `! Cache-Control` then `Cache-Control: public, max-age=31536000, immutable`.
    - The renderer throws if the baseline lacks `script-src` or `connect-src`, if a token is already present, if the baseline already contains any `Cache-Control` or global `X-Robots-Tag` line or a `/bundles/*` or `/web-ml/*` rule, or if any line exceeds 2,000 characters or rules exceed 100. Rendering is therefore single-pass by construction.
    - `public/_headers` stays the baseline: security headers, CSP and the fragment crawler rules only. It never contains the cache or global crawler lines, which exist only in rendered output (`dist/_headers`, `dev/_headers` and test variants). `_headers` emission in dev mirrors production.
- Effective production headers (via `scripts/headers-file.ts`): `/`, `/data`, `/index.html`, `/release.json`, `/robots.txt` and every `index.json` give exactly one `Cache-Control: public, max-age=0, must-revalidate`; `/assets/linear-regression.svg` also revalidates; `/bundles/app.<hash>.js`, workers, chunks and `/web-ml/<version>-<digest>/…` give exactly one `Cache-Control: public, max-age=31536000, immutable`; isolation and CSP apply to all.
- `scripts/headers-file.ts` exports `parseHeadersFile(text): HeaderRule[]` and `resolveHeaders(rules, pathname): Headers`. Patterns are absolute paths with at most one `*` (any characters, including `/`). Rules apply in file order, a repeated header is joined with `, `, and `! Name` deletes values accumulated so far. Comments start with `#`. Malformed input throws.
- **Crawler policy (`crawlerPolicy`):** the closed artefact writes `robots.txt` as `User-agent: *` LF `Disallow: /` LF and adds the global header. `public` (allowed only for a production build of a stable version ≥ `1.0.0`; anything else throws) writes `User-agent: *` LF `Allow: /` LF and omits the global header while keeping fragment rules. An unknown value throws. A version bump alone never opens crawling. The deploy job passes `closed`. `public/robots.txt` holds the closed form.
- **V1 opening and edge enforcement (maintainer runbook, documented in T7):** before announcing the beta, add a Cloudflare WAF custom rule with the Block action. It applies when `http.host eq "beta.samata.ml"` and `http.request.uri.path ne "/robots.txt"`, and either `cf.verified_bot_category in {"Search Engine Crawler" "AI Crawler" "AI Search" "AI Assistant"}` or `lower(http.user_agent)` contains any of `googlebot`, `bingbot`, `gptbot`, `oai-searchbot`, `chatgpt-user`, `claudebot`, `claude-searchbot`, `claude-user`, `perplexitybot` or `perplexity-user`. Check rule order against Skip rules, and confirm that managed robots directives do not alter the deny-all file. If the zone lacks the category field, use the UA list and report the narrower enforcement. For V1, the maintainer deploys `public` deliberately, verifies live responses, and removes the rule only if the beta hostname itself opens.
- **Limits:** Robots directives are voluntary, and unidentified automation may still fetch pages. Version URLs on `workers.dev` are outside the WAF rule but serve the closed artefact.

#### C. Worker failures and stale-release notice

- `src/common/release/worker-failures.ts` (framework-free): `type WorkerFailureCode = 'storage-worker-error' | 'storage-worker-protocol-error' | 'training-worker-startup-failed' | 'training-worker-crashed' | 'training-worker-protocol-error' | 'analysis-worker-failed'`, `reportWorkerFailure(code): void`, `onWorkerFailure(listener: (code) => void): () => void` and `resetWorkerFailuresForTests(): void`. - Storage: `createStorageClient(port: MessagePort | Worker, options: { workerEvents?: EventTarget } = {})` attaches `error` and `messageerror` listeners to `options.workerEvents`. `getStorageClient()` passes the spawned `Worker` as both `port` and `workerEvents`, and tests pass a plain `EventTarget` alongside their in-memory port. On either event, reject every pending request with `IngestionError('STORAGE_FAILED', 'The storage worker stopped.')`, dispose the client, clear the `getStorageClient()` singleton so the next call spawns a fresh worker, and report `storage-worker-error` or `storage-worker-protocol-error` once per client.
- Training: the settlement branches at L442, L443 and L447 report `training-worker-crashed`, `training-worker-protocol-error` and `training-worker-startup-failed` before their existing settlement, leaving codes and recovery unchanged. Analysis: `fail()` reports `analysis-worker-failed` when triggered by `onerror` or `onmessageerror` (not `dispose()`).
- `src/common/release/stale-release.ts` (framework-free): `$staleAssetDetected: ReadableAtom<boolean>`, `checkForNewerRelease(fetchImpl: typeof fetch = fetch): Promise<void>`, `installStaleReleaseDetection(): () => void` (subscribes to worker failures and calls the check) and `resetStaleReleaseForTests(): void`. The shell renders, at the top of `<main id="content">`, `<div class="notification notification-alert" role="alert">` with the message “A newer version of samatā.ml is available. #### D. Beta acceptance and Umami Cloud

- **Onboarding state:** the in-memory type gains `onboarding.betaTelemetryAccepted: boolean`, and `INITIAL_APP_STATE` sets it to `false`. In stored v1 blobs the field is optional. `validateAppState` (persister L140–L142) normalises an absent field to `false` and treats a present non-boolean value as invalid, as it does for `welcomeDismissed`. `acceptBetaTelemetry(): void` in `src/stores/app.store.ts` sets both flags to true in one update. `isSynchronousChange` and `isProgressOnlyChange` compare `betaTelemetryAccepted` exactly as they compare `welcomeDismissed`, so acceptance is written immediately. Dismissal alone never implies acceptance.
- **Cross-tab acceptance (the only onboarding field shared between tabs):** add `mergeOnboarding(local, other): PersistedAppState['onboarding']` in `src/stores/persister.ts`. It returns `{ welcomeDismissed: local.welcomeDismissed || other.betaTelemetryAccepted, betaTelemetryAccepted: local.betaTelemetryAccepted || other.betaTelemetryAccepted }`. Use it at L613 (`current` with the newer snapshot), L792 (`captured` with the stored state being merged) and L868 (`local` with the candidate), so no write can clear a stored acceptance. `welcomeDismissed` otherwise stays per tab. Add `adoptStoredBetaAcceptance(): void`: it reads `readAppSnapshot()`, and when the stored state is valid with acceptance true and the local flag is false, it sets both local flags true. The shell's `storage` listener (`src/app.ts` L253–L261) calls it after `refreshTrainingSnapshot()`. Adoption closes an open beta dialog through the existing synchronised close, starts telemetry in that tab, and never sends `beta_get_started`. Specify this in `state-and-storage.md` §§3, 5 and 7.
- **Welcome behaviour when `isBetaTelemetryDeployment()` is true:** the dialog opens on root and workflow routes while acceptance is false, including for users with `welcomeDismissed: true`. After the existing body it renders `<p id="welcome-beta">` with “By clicking Get Started, you accept cookieless analytics and error reporting for this beta.” followed by a space and `<a href="/privacy">Read the privacy policy</a>`, before **Get Started**. The dialog gets `aria-describedby="welcome-beta"`. **Get Started** calls `acceptBetaTelemetry()`. The modal reads the deployment gate from `$betaDeployment` (below), so stories and tests can render the beta state without changing the closed API. A `cancel` listener calls `preventDefault()`. If the dialog still closes without a synchronised close (browsers may ignore repeated cancel prevention), `handleClose` records nothing and requests an update, so `updated()` reopens it with `showModal()`. Clicking the privacy link navigates through the router, which is a route-driven hide that records nothing, and returning to a workflow route reopens the notice. Outside the beta gate, existing behaviour and copy are unchanged. The component's closed API stays tag-only.
- **Script lifecycle (`src/common/telemetry/telemetry-client.ts`, framework-free):** `isBetaTelemetryDeployment(): boolean` returns `BETA_TELEMETRY_ENABLED && location.hostname === 'beta.samata.ml'`. `$betaDeployment: ReadableAtom<boolean>` is initialised from it. `setBetaDeploymentForTests(value: boolean): void` (TSDoc: tests and stories only) overrides it. `initBetaTelemetry(isAccepted: () => boolean): void` is idempotent; while disabled or unaccepted it does nothing. On the first accepted call it defines `window.samataUmamiBeforeSend`, then appends one `<script defer>` with `src="https://cloud.umami.is/script.js"`, `crossorigin="anonymous"`, `referrerpolicy="no-referrer"`, `data-website-id` (supplied ID), `data-domains="beta.samata.ml"`, `data-auto-pageview="false"`, `data-exclude-search="true"`, `data-exclude-hash="true"`, `data-fetch-credentials="omit"` and `data-before-send="samataUmamiBeforeSend"`. It sets no `data-errors`, `data-performance`, `data-tag`, `data-distinct-id`, `data-release` or `data-environment`. The client attaches its own `load` and `error` listeners to the element before appending it. An `error` event, or a `load` event after which `window.umami?.track` is not a function, marks the client failed: everything is dropped, nothing retries and nothing throws.
- **Sends:** the client keeps `currentPath: BetaPagePath`, updated from the route store (model-detail routes collapse to `/models`). Reserved routes leave it unchanged, and it starts at `/`. `trackBetaPageview(path)` calls `umami.track(props => ({ ...props, url: path }))`. Every named event uses the callback form with the canonical URL: `umami.track(props => ({ ...props, url: currentPath, name }))`. `trackBetaEvent(name: BetaEventName)` sends `name`. `reportBetaException(code: BetaExceptionCode)` sends `'beta_error_' + code` with hyphens replaced by underscores, at most once per code per document. The string form `umami.track(name)` is never used, because the tracker would supply its own `url`. `BetaPagePath` is `'/' | '/data' | '/target' | '/models' | '/results'`, and model-detail routes collapse to `/models`. Reserved routes send nothing, and a repeated identical path sends nothing. `BetaEventName` is `beta_get_started`, `sample_dataset_selected`, `custom_dataset_uploaded`, `training_started`, `training_completed` or `training_failed`. `BetaExceptionCode` is `window-error`, `unhandled-rejection` or any `WorkerFailureCode`. The complete event-name allowlist is those six names plus `beta_error_window_error`, `beta_error_unhandled_rejection`, `beta_error_storage_worker_error`, `beta_error_storage_worker_protocol_error`, `beta_error_training_worker_startup_failed`, `beta_error_training_worker_crashed`, `beta_error_training_worker_protocol_error` and `beta_error_analysis_worker_failed`. Before the script is ready, only the pending initial pageview and the `beta_get_started` event are queued (in memory, at most one each). Everything else is dropped. No call throws or returns a rejected promise.
- **Hook points:** app-owned window `error` and `unhandledrejection` listeners report `window-error` and `unhandled-rejection` without inspecting the error. The worker codes come from `onWorkerFailure`. Workflow events are sent only by the tab that performed the action:
    - `startDatasetLoad` success, sent inside the active-controller guard (`dataset.store.ts` L343–L346), never after it: `source.kind` `'sample'` sends `sample_dataset_selected`, and `'file'` sends `custom_dataset_uploaded`.
    - `training-service.ts` `train()`: `training_started` immediately after `setTrainingSessionStatus(identity, 'running')` (L545), and `training_completed` immediately after `'complete'` (L602).
    - `training_failed`, at most once per run ID (tracked in a `Set` in the telemetry client), in three owner paths:
        - the start acknowledgement ends as `'failed'` (L536–L542);
        - `start()` sets a pending session to `'failed'` (L654–L655);
        - `settleStopped` (L486–L498) computes status `'failed'` and its `repairStopped(…, 'finish')` call returns `ok`.
          Nothing is sent from `repairStopped` itself, because `retry` recovery also calls it with `'recover'` (L754).
    - `observePublishedStops`, `retry`, `recoverCompletedResult`, `recoverStoppedPublication`, storage-event refreshes and reloads never send. `beta_get_started` is sent only in the document whose click records acceptance.
- **`before-send` allowlist:** `samataUmamiBeforeSend(type, payload)` returns `false` unless the deployment gate is open, acceptance is true, `type === 'event'` and `payload` is a plain object without a nested `payload` key. It returns a new object containing only:
    - `website`, which must equal the supplied ID;
    - `hostname`, which must equal `beta.samata.ml`;
    - `url`, which must be a `BetaPagePath`;
    - `screen`, only if it matches `^\d{1,5}x\d{1,5}$`;
    - `language`, only if it matches `^[A-Za-z]{2,3}(-[A-Za-z0-9]{1,8}){0,3}$`;
    - `name`, which must be in the event allowlist when present.

    Any other value for a required field rejects the payload. `referrer`, `title`, `tag`, `id`, `salt`, `data` and every other key are omitted. Identify, performance, error and unknown types are rejected.
