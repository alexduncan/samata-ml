## Goal

**Current behaviour:** Single-model results (`src/features/results/app-model-results.ts`) and model comparison (`src/features/results/app-results-view.ts`) render seven Observable Plot charts, one HTML flowchart, and comparison/confusion tables through `PlotController` (`src/features/results/charts/plot-controller.ts`) on `@observablehq/plot@0.6.17`. Several visual, statistical, and accessibility defects exist across these charts:

- `PlotController` does not enforce a `>= 12px` minimum font size, does not wire `aria-describedby`, does not mark Plot data `<g>` groups `aria-hidden="true"`, and does not re-render when user text size changes.
- `app-fold-strip` connects unordered models with `lineY` (`strokeOpacity: 0.6`, 2.14:1 composite contrast on `#fff` and 2.11:1 on `--stone-50`), hides `y` axis labels inside the plot, omits the `x` axis label, clips baseline annotations (`marginLeft`/`marginRight: 14`), silently clamps `±1 SD` to `[0, 1]`, omits chart-level interval labels, and wraps colours at six (`index % 6`).
- `app-classee-strips` reuses `--chart-1..6` without a legend or direct predicted-class labels (colour-only), draws adjacent stacked bars touching at 1.08–1.33:1 contrast, omits axis labels and gridlines, uses hardcoded character/row geometry, and reads `--surface` via `getComputedStyle(this)`.
- `app-reliability-diagram` renders a non-square rectangle (`height: 296`), places `"Perfect calibration"` in the bottom-right corner away from the diagonal, omits `(%)` axis units, reports ECE as a decimal, omits `zero: true`/integer ticks/gridlines/`ariaDescription` on `.counts`, and shows only supported observed rates and bin totals in its table.
- `app-threshold-explorer` produces duplicate rounded integer y-ticks on small counts (`0, 1, 1, 2, 2`), omits y-gridlines, omits `(%)` and positive class name on the x-axis, leaves the cutoff `ruleX` unlabelled on the chart, places `<details>` outside `<figure>`, lacks an `aria-live="polite"` update announcement, uses a static encoding takeaway, and omits `"x of y"` counts beside TPR/FPR.
- `app-class-error-bars` renders at Plot's `10px` default font size, omits its x-axis label (`lower is better`), gridlines, and explicit ticks, wraps at six colours, uses hardcoded margins/row height that break at 320px/200% text size, and omits error counts (`x of y`) and `.number` table alignment.
- `app-rope-bar` renders at `10px`, draws `--chart-axis` text over dark bars (1.10–1.21:1 contrast), draws adjacent segments without separator strokes (1.09–1.33:1), collides centered labels on narrow/0% segments, hides the quantitative x-axis, uses fixed `--chart-1/2/3` and `"A higher"`/`"B higher"` instead of compared model identities, takes `ropeWidth` as a `0.001–0.1` decimal rather than percentage points, omits `"x in 100"` frequency framing, lacks `aria-live="polite"`, and has `<input>`/`<button>` controls under 24px.
- `app-instance-agreement` renders at `10px`, omits axis labels, `zero: true`, `nice: true`, integer ticks (producing duplicate ticks `0, 1, 1, 2, 2, 3, 3` at `max = 3`), and y-gridlines, overlaps long bucket labels at 320px/200% text size, uses `--chart-1`, and omits `.number` and `%` in its table.
- `app-confusion-flowchart` is not wrapped in `<figure>`/`<figcaption>`, reuses `--chart-1`/`--chart-5`, and omits percentages beside outcome counts.
- `app-comparison-table` draws truncated `min..max` `.bar` strips ignoring metric direction, lacks `24px` sort buttons, and lacks model swatches and labels.
- `app-results-view` keeps an `<h2>` only on the metrics table (omitting `<h2>` headings for its other five chart/analysis sections for six ordered sections total), overrides resolved model names with `Model {n}`, and lacks `aria-live="polite"` announcements on group/selection changes; `app-confusion-matrix` and `app-confusion-delta` lack `aria-live="polite"` on `> 20`-class filter changes and use generic `"True class"`/`"Predicted class"` wording; ROC-AUC, Average precision, and ECE display as decimals while other `0–1` scores display as percentages.

**Target behaviour:** Every chart and visual table in Section 6 (`/models/{num}`) and Compare Results (`/results`) conforms to WCAG 2.2 AA and the repository's chart design principles (upgraded to `@observablehq/plot@0.6.18`):

- `PlotController` enforces `>= 12px` scaling text (`max(12px, 0.75rem)`), `aria-hidden="true"` on every mark `<g>`, `role="img"` + `aria-label` + `aria-describedby` on every chart SVG, and responsive re-rendering on container resize and text-size zoom.
- On `/results`, every chart and table consistently identifies each model by its assigned `modelColor`, numbered `.swatch` badge (`modelSwatchStyles`), deterministic Plot marker symbol, and `modelLabel` (documented as an explicit project-specific exception in `specification/charts.md` and `specification/visual-design.md`), with WCAG 1.4.11 outlines on `amber`, `--model-swatch-ink` on `amber`/`sky`/`--chart-neutral`, and `--surface` separators on adjacent stacked segments.
- Score metrics use one app-wide `0–100%` convention: ROC-AUC, Average precision, and ECE display as percentages (`0–100%`), ROPE practical-equivalence width displays and edits in percentage points (`0.1–10 pp`, stored as `0.001–0.1` for v1 compatibility), while MCC, Log loss, and Brier score stay 3-decimal numbers.
- `app-comparison-table` removes truncated inline `.bar` strips; `app-fold-strip` removes cross-model `lineY` connecting lines (`paired` removed); every chart has visible labelled axes with units/direction, round non-duplicate ticks, gridlines, data-generated neutral takeaways and descriptions, frequency/count framing (`x of y` / `x in 100`) where supported by stored data, `<figure>`/`<figcaption>` + `<details>` tables, `>= 24px` controls, and `aria-live="polite"` announcements for interactive changes.
- A dedicated `specification/charts.md` codifies all lasting chart design rules and the `ModelColor` exception, cross-referenced from `specification/README.md`, `COMPONENTS.md`, `visual-design.md`, `testing.md`, `workflow-steps.md`, and the results component specs.

**Why:** Make every classification result and comparison chart accurate, visually unambiguous, accessible to keyboard, screen-reader, low-vision, and colour-vision-deficient learners, and backed by a single durable specification that governs future Phase 6 and Phase 7 charts.

**Constraints and invariants**

- **Repository boundary:** Never compute new metrics, curves, calibration bins, or Bayesian posteriors in `samata-ml`; only project, format, and render stored upstream results (`StoredEvaluation` and `RopeView`).
- **Storage compatibility:** `ComparisonUi.ropeWidth` remains stored as a `0–1` fraction (`0.001–0.1`) in `$appState` and sent unchanged to `src/features/results/analysis.worker.ts`; only the UI presentation/input converts to and from percentage points (`0.1–10` in `0.1` steps, default `1`).
- **Closed token vocabulary:** Use only tokens defined in `css/root.css` (including `--pink-700`, `--sky-600`, `--olive-700`, `--model-swatch-ink` from `model-training-workflow.md`), with zero literal colours and zero `var()` fallbacks.
- **WCAG 2.2 AA:** Text >= 4.5:1 (3:1 large), graphical marks/outlines/focus rings >= 3:1 against adjacent colours, colour never the sole cue (1.4.1), live text >= 12px scaling cleanly to 200% text size and 320px/400% zoom without 2D scrolling, >= 24×24 CSS px interactive targets (2.5.8), keyboard operability, `aria-live="polite"` updates (4.1.3), and zero axe violations.
- **Lit and i18n discipline:** Presentational components never import stores or `src/i18n.ts`; all strings flow through typed `labels` props built by `app-model-results` or `app-results-view`. Every modified element has a closed public API and co-located `*.stories.ts` coverage.
- **British English:** All prose, UI strings, comments, and specifications use British English.

**Implementation order across plans**

- Start after [model-training-workflow.md](model-training-workflow.md) is integrated on `main`. This plan consumes its `ModelColor` union (`'amber' | 'blue' | 'teal' | 'purple' | 'red' | 'green' | 'pink' | 'sky' | 'olive' | 'neutral'`), `ModelRecord.modelColor`, `ModelRecord.modelLabel`, root tokens (`--pink-700`, `--sky-600`, `--olive-700`, `--model-swatch-ink`), and shared `modelSwatchStyles` (`src/styles/model-swatch.styles.ts`).

### Interfaces and behaviour

#### 1. `PlotController` (`src/features/results/charts/plot-controller.ts`)

- `CHART_TOKEN_NAMES`: expand `as const` tuple to include the existing 9 `--chart-*` tokens plus `--surface`, `--stone-50`, `--stone-900`, `--model-swatch-ink`, `--amber-500`, `--blue-700`, `--teal-700`, `--purple-700`, `--red-700`, `--green-800`, `--pink-700`, `--sky-600`, `--olive-700`, `--neutral-600`.
- `ChartTokens`: `Readonly<Record<ChartTokenName, string>>` (derived from expanded `CHART_TOKEN_NAMES`).
- `ChartLibrary`: unchanged `Pick<typeof Plot, 'plot' | 'barX' | 'dot' | 'rectY' | 'lineY' | 'ruleX' | 'ruleY' | 'text'>`.
- `PlotRenderer`: `(chart: ChartLibrary, tokens: ChartTokens, width: number, fontSizePx: number, measureText: (text: string) => number) => SVGSVGElement | HTMLElement | null`. The controller always supplies all five arguments; existing renderers accepting fewer remain compatible. The fourth argument carries `parseFloat(getComputedStyle(host).fontSize) || 16` so charts scale margins and row heights. The fifth argument is a synchronous, controller-owned measurement callback available during the very first invocation; `app-fold-strip`, `app-classee-strips` and `app-class-error-bars` accept it and pass it to both fitting helpers. They do not retain it after the render callback returns.
- `PlotController` constructor: `constructor(host: PlotHost, getContainer: () => HTMLElement | null, render: PlotRenderer, getDescribedBy?: () => string | null)`.
- Behaviour:
    - Creates and observes a visually hidden `1rem` probe element (`inline-size: 1rem; block-size: 0; position: absolute; visibility: hidden; pointer-events: none`) inside the chart wrapper/shadow root using its `ResizeObserver` (cleaned up on `hostDisconnected()`), alongside observing the chart container. When root `font-size` changes (e.g. 200% text-only zoom `html { font-size: 32px }`), the probe's `clientWidth` changes (`16` -> `32`), reliably triggering `schedule()` and re-rendering with the updated `fontSizePx` even when `.chart`'s pixel width is unchanged.
    - `normalise(chart)`: sets `chart.style.fontFamily = 'inherit'`, `chart.style.maxInlineSize = '100%'`, and `chart.style.fontSize = 'max(12px, 0.75rem)'` (never below 12px; scales at 200% text size). For the root `<svg>` (or nested `<svg>`): ensures `role="img"` whenever `aria-label` is present; sets `aria-describedby` to `getDescribedBy?.()` when non-empty; strips every descendant `[aria-label]` and sets `aria-hidden="true"` on every Plot data-mark `<g>` child (direct `<g>` children of `<svg>` without `aria-hidden="true"` that are not already hidden axis groups, or all `<g>` children inside `<svg>` since the chart is a single `role="img"` element whose full content is in `aria-label`, `aria-describedby`, and the `<details>` data table).

- `resolveModelMarkStyle(color: ModelColor, tokens: ChartTokens): ResolvedModelMarkStyle`:
    - Filled symbols (`!stroked`): `dotFill = tokens[token]`, `dotStroke = outlineRequired ? tokens['--stone-900'] : tokens['--surface']`, `dotStrokeWidth = outlineRequired ? 1.5 : 1`. Always pair with explicit `r: 5` on `Plot.dot` (since Observable Plot defaults `r` to `3` for constant symbols).
    - Stroked symbols (`stroked`): `dotFill = 'none'`, `dotStroke = tokens[token]`, `dotStrokeWidth = 2`.
    - Bars/segments: `fill = tokens[token]`, `barStroke = outlineRequired ? tokens['--stone-900'] : tokens['--surface']`, `barStrokeWidth = 1.5`, `ink = tokens[inkToken]`. The `--stone-900` outline on `amber` applies strictly to chart marks, bars, and chart-legend swatches in `chart-encoding.ts` and `results.styles.ts` (leaving `src/styles/model-swatch.styles.ts` untouched).
- `DATASET_CLASS_TOKENS: readonly ChartTokenName[] = ['--chart-1', '--chart-2', '--chart-3', '--chart-4', '--chart-5', '--chart-6']`.
- `PLOT_SYMBOL_PATHS: Readonly<Record<ModelPlotSymbol, string>>`: 16×16 viewBox SVG path strings matching Observable Plot's symbol geometry for accessible HTML legends (`<svg aria-hidden="true" viewBox="-8 -8 16 16">`). Stroked symbols (`plus`, `times`) render `<path>` with `fill="none"`, `stroke` set to the model colour token, and `stroke-width="2"`; filled symbols render with `fill` set to the model colour token (`stroke="var(--stone-900)"` and `stroke-width="1.5"` for `amber`, `stroke="none"` for the other 7 filled symbols).
- `integerTicks(min: number, max: number, targetCount?: number): number[]`: supports both non-negative ranges `[0, max]` (`min = 0`) and signed diverging ranges `[-maxErrors, maxCorrect]` (`min <= 0 <= max`, as in `app-classee-strips`), always including `0`, returning strictly increasing unique integers with zero duplicates (exact whole numbers when `max - min <= 6`, e.g. `max = 1..3` on `[0, max]` or `[-2, 3]`, and 4–7 round whole-number ticks using `1, 2, 5 × 10^k` steps for larger spans).
- `computeAxisMargin(labels: readonly string[], fontSizePx: number, containerWidth: number, measureText: (text: string) => number, maxFraction?: number): { readonly margin: number; readonly labelWidth: number }`: default `maxFraction = 0.38`; set `upper = Math.floor(containerWidth * maxFraction)` and `lower = Math.min(Math.ceil(fontSizePx * 4), upper)`. Reserve `Math.ceil(fontSizePx * 0.5)` pixels within the margin for the tick/axis gap and outer inset, and clamp `Math.ceil(maximum measured label width + reserved space)` to `[lower, upper]` (empty labels have maximum width 0); return `labelWidth = Math.max(0, margin - reserved space)`. The cap limits this axis margin, not the combined margins; at 320px width and 32px font size both effective bounds are 121px. `truncateLabel(label: string, labelWidth: number, measureText: (text: string) => number): string` returns the original if it fits; otherwise return the longest grapheme-cluster prefix plus `…` whose measured width fits, or an empty string if the ellipsis alone does not fit. Segment graphemes using `Intl.Segmenter` with `granularity: 'grapheme'`; retain the full original label in the associated accessible table.
- Before the initial renderer invocation, once the connected chart container exists, the controller attaches a visually hidden SVG text probe to the chart wrapper. Set the probe and rendered chart axis text to the same inherited family, weight, style, letter spacing and direction and `font-size: max(12px, 0.75rem)`; measure its `getComputedTextLength()` synchronously after setting `textContent`. The fifth renderer argument closes over that attached probe, so no previously rendered chart is needed for first render. Use the same measurement for the margin and each fitted label; do not infer width from character counts. Schedule another render after container resize, root-font-size probe changes, label updates and `document.fonts` `loadingdone`; register the font listener once on connection, unregister it and remove the probe on disconnect, and recreate both on reconnection. The 1rem resize probe still schedules updates at constant chart width. Browser checks compare actual SVG label and chart bounds after initial render, font loading, resizing and reconnection, including wide `W`/`M` labels.
