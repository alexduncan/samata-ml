## Goal

**Current behaviour:** Eleven sample CSVs are tracked under `content/datasets/`. COMPAS already downloads directly from ProPublica when selected. The generator accepts a tracked CSV or a direct remote descriptor. Both `content/datasets/` and the former `public/datasets/` paths appear in the history reachable from `main`. Three source-rights cases require particular care: ProPublica restricts redistribution of COMPAS, and the current Pima Diabetes and Titanic licence claims lack confirmed rights-holder evidence.

**Target behaviour:** Ten retained samples keep their data bytes and modelling defaults. Titanic remains available as a separate sample derived from the published 1912 British inquiry. Eight samples are fetched and prepared during the build and served from Samata’s origin, and three are fetched directly in the browser. Pima Diabetes and the old Seaborn Titanic ID stop accepting new loads. Saved projects keep their metadata guidance. The source checkout tracks no full sample CSV. A reviewed first-push procedure filters all historical copies of the twelve CSVs from the publication clone while retaining ordinary project history.

**Why:** Keep dissertation results reproducible with pinned data, respect upstream terms, and give supervisors a readable entry point to the repositories and milestone evidence.

## Scope

**In scope**

- Dataset provenance, verified acquisition and catalogue delivery for all twelve current samples.
- Existing saved datasets, source copy and applicable regression tests.
- A dataset-specific first-push runbook for `samata-ml` and a README review entry point. The maintainer uses the same main-only publication convention for `web-ml`, keeping its existing history.

**Out of scope**

- Pushing, changing remotes, or filtering any existing shared or working repository. The actual first publication is a maintainer operation after implementation and closure.
- General history squashing, library changes, code-licence selection, dataset substitution beyond the documented Titanic replacement, new modelling or metrics.
- Uploading user data, adding an app-side proxy, externalising generated documentation, or changing the approved visual layout.

**Constraints and invariants**

- Retained IDs, CSV bytes, ordering, schemas, modelling defaults and generated descriptor/index v1 shapes remain compatible. Runtime `csvOrigin` describes browser delivery.
- Published datasets retain their attribution, licence and transformation notices. Remote availability alone does not establish a licence. The filter removes all full samples being externalised or withheld, including the old COMPAS copy.
- User-uploaded and already ingested data remain local. Publisher CSV requests omit credentials and referrers and carry no uploaded data or user identifiers. The standard CORS Origin header still identifies the app origin. Keep COOP `same-origin`, COEP `require-corp`, CORP `same-origin` for Samata assets and the existing policy for unrelated CSP directives.
- No raw CSV, expanded ZIP, generated output, raw-byte fixture, reconstructed full sample or private Git publication artefact enters the source tree. Small synthetic test CSVs may remain tracked.
- Browser/UI changes use the existing Lit owner, i18n, native controls, tokens and WCAG 2.2 AA rules.

#### Titanic replacement

- Author a descriptor and datasheet at `content/datasets/titanic-inquiry/`. Use card name **Titanic Survival (1912 British Inquiry)**. Credit the British Wreck Commissioner’s Inquiry and cite the [National Archives on expired pre-1957 published Crown material](https://www.nationalarchives.gov.uk/terms-and-conditions/copyright/copyright-and-related-rights/), the report's [numbers saved](https://www.titanicinquiry.org/BOTInq/BOTReport/botRepSaved.php), and [Dawson’s teaching dataset and discussion](https://jse.amstat.org/v3n3/datasets.dawson.html). The dated report supplies the numeric facts. The R-derived CSV transports those facts and uses conventional categorical labels. Do not copy the report’s prose, later editorial material or the Seaborn records. In the descriptor use `LicenseRef-Public-Domain` with the National Archives link and explicit underlying provenance. The plan does not relicense the mirror or R software.
- Download the compact CSV at build time. Require exact header `rownames,Class,Sex,Age,Survived,Freq` and 32 unique combinations from Class `1st/2nd/3rd/Crew`, Sex `Male/Female`, Age `Child/Adult` and Survived `No/Yes`. Validate canonical, non-negative integer counts and exact totals before allocating output. Iterate input order, emitting one row per count, zero rows for empty cells. Omit rownames and frequencies. Write the header `passenger_class,sex,age_group,survived` followed by LF-separated rows and one final LF. Preserve Class, lowercase Sex and Age, and map No/Yes to `0/1`. Enforce the output hash and length before profiling. This transformation reconstructs the table's cell counts and neither recovers individual records nor performs model preprocessing.
- Mark all four fields categorical. Use only one target candidate `survived` with positive class `'1'`, no extra candidate or generated predictor, and mark sex as sensitive. Verify 711 survivors and 1490 deaths, class totals 325, 285, 706 and 885 in the order 1st, 2nd, 3rd and Crew, and survivors 203, 118, 178 and 212 respectively. Include the categorical age and lack of fare, names and family attributes. Explain repeated rows are people within the same published stratum, should not be interpreted as independent validation of novel feature profiles, and make this a descriptive teaching and modelling example.
- Use the same supported classifier selection path as existing samples. Tests assert the exact prepared digest, coverage of all 32 input cells, absence of a counted-row column or individual identifier and the normal card-to-binary-target workflow. Keep the fresh ID separate because saved sample metadata records a sample ID but no source digest. The old ID must never resolve against these columns.
