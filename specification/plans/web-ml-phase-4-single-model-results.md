## Goal

**Current behaviour:** Phase 3 is implemented and archived. View Results acknowledges an already-published training result and focuses Section 6 on the same route through `app-model-builder-view.ts` L1776–1788 and `training-service.ts` L1071–1105. Section 6 still renders the pending notice (builder L2218–2224). The IndexedDB v1 envelope already contains protocol-specific results and fitted artefacts. There is no shared Section 6 view or `StoredEvaluation`.

**Target behaviour:** After Phase 3 training completes and the user selects **View Results**, Section 6 (`6. Model Results`) renders the **shared base** metrics and visuals that apply to every classifier ([metrics-and-visuals note §1 Shared Base](../notes/metrics-and-visuals.md)): balanced accuracy as the headline, raw accuracy with the zero-rule baseline delta, macro-F1, per-class precision and recall, outer-fold spread (SD and IQR) with a dot-and-interval strip, a binary confusion flowchart or a multiclass Classee strip, a "More metrics" disclosure (MCC, ROC-AUC, average precision, log-loss, Brier, ECE), an interactive probability-threshold histogram for binary targets, a reliability diagram with a confidence histogram, and a train–test gap diagnostic card. Upstream outputs are retained in a versioned `StoredEvaluation` that Phases 5–7 also read.

**Why:** Give learners an honest, imbalance-aware first view of one model (VISION §5, §8, §10) and fix the persisted evaluation contract and chart foundation once, so comparison (Phase 5), model-specific internals (Phase 6) and tuning results (Phase 7) extend it rather than reshape it.

**Constraints and invariants**

- Every metric, curve, baseline, partition and per-row prediction comes from `web-ml` (umbrella [WR ledger](web-ml-classification-integration.md#scope)). `samata-ml` computes only fold aggregation (mean, sample SD, IQR), the partition fingerprint, unit conversions (e.g. percentages), differences between already reported values and layout.
- Reported scores are out-of-sample: One-Shot test rows or outer-fold held-out rows. Training-partition reports appear only as the labelled generalisation gap.
- Stored metrics use the model's own prediction rule. The threshold explorer is exploratory: it never changes stored metrics, `ModelRecord.metrics` or Phase 5 comparisons.
- Strict TypeScript, Bun only, TSDoc on exported symbols, native semantic tables, WCAG 2.2 AA, British English, `@nanostores/i18n` (`COMPONENTS.md` §1, §7, §8). Colour is never the only carrier of meaning: every chart has text labels or positions that carry the same information, and a native data table alternative.
- Never read `../web-ml/src/**` or `../web-ml/specification/internals/`; never modify `../web-ml` or `node_modules/`; `bun.lock` changes only through T2's `bun add`.

### Interfaces and behaviour

#### A. `StoredEvaluation` (`src/types/model-evaluation.ts`)

```ts
/** Class labels exactly as the target column stores them. */
export type StoredClassLabel = string | number | boolean;

export type MetricUnavailableReason =
	| 'not-requested'
	| 'probabilities-unavailable'
	| 'unseen-validation-labels'
	| 'undefined-for-validation-classes'
	| 'all-targets-zero'
	| 'negative-targets'
	| 'not-applicable'
	| 'insufficient-degrees-of-freedom'
	| 'single-class';

export type StoredMetric =
	| { readonly available: true; readonly value: number }
	| { readonly available: false; readonly reason: MetricUnavailableReason };

export interface StoredReport {
	readonly sampleCount: number;
	readonly accuracy: number;
	/** Macro recall. */
	readonly balancedAccuracy: number;
	readonly macroF1: number;
	readonly mcc: StoredMetric;
	readonly rocAuc: StoredMetric;
	readonly averagePrecision: StoredMetric;
	readonly logLoss: StoredMetric;
	readonly brier: StoredMetric;
	/** Each length K, `classLabels` order. */
	readonly precisionPerClass: Float32Array;
	readonly recallPerClass: Float32Array;
	readonly f1PerClass: Float32Array;
	readonly support: Uint32Array;
	readonly predictedCount: Uint32Array;
	/** Row-major K × K; rows = true class, columns = predicted class. */
	readonly confusionMatrix: Uint32Array;
}

export interface StoredPartition {
	readonly index: number;
	readonly kind: 'holdout-test' | 'outer-fold';
	readonly trainSampleCount: number;
	readonly testSampleCount: number;
	readonly durationMs: number;
	readonly timing: 'holdout-fit' | 'fold-fit-and-score';
	readonly test: StoredReport;
	/** Training-partition report (WR-4). */
	readonly train: StoredReport;
	readonly baselines: { readonly mostFrequent: StoredReport; readonly stratified: StoredReport };
}

export interface StoredOutputs {
	/** Ascending dataset row indices of every evaluated row. */
	readonly sourceRowIndex: Uint32Array;
	readonly partitionIndex: Uint16Array;
	readonly trueIndex: Uint16Array;
	readonly predictedIndex: Uint16Array;
	/** rowCount × K, `classLabels` order; null when the model has no probabilities. */
	readonly probabilities: Float64Array | null;
	readonly probabilitySource:
		| 'native'
		| 'leaf-frequency'
		| 'neighbor-vote'
		| 'network-output'
		| 'platt'
		| null;
	readonly positiveScores: Float64Array | null;
	readonly rankingScoreSource: 'probability' | 'decision-function' | null;
}

export interface StoredCurves {
	/** 101 cutoffs 0.00…1.00 on the positive-class probability; binary with probabilities only. */
	readonly thresholdSweep: {
		readonly thresholds: Float64Array;
		readonly tp: Uint32Array;
		readonly fp: Uint32Array;
		readonly tn: Uint32Array;
		readonly fn: Uint32Array;
		readonly tpr: Float64Array;
		readonly fpr: Float64Array;
	} | null;
	/** Ten uniform bins: binary = positive class; multiclass = top-label confidence vs correctness. */
	readonly calibration: {
		readonly meanPredicted: readonly (number | null)[];
		readonly observed: readonly (number | null)[];
		readonly count: Uint32Array;
		readonly expectedCalibrationError: number;
	} | null;
	/** One entry for the positive binary class, otherwise entries in class-axis order. */
	readonly ranking:
		| readonly {
				readonly classIndex: number;
				readonly roc: { readonly fpr: Float64Array; readonly tpr: Float64Array } | null;
				readonly precisionRecall: {
					readonly recall: Float64Array;
					readonly precision: Float64Array;
				} | null;
		  }[]
		| null;
}

export interface StoredEvaluation {
	readonly schemaVersion: 1;
	readonly protocol:
		| { readonly kind: 'one_shot'; readonly testRatio: number; readonly randomState: number }
		| {
				readonly kind: 'cross_validation';
				readonly folds: number;
				readonly randomState: number;
		  };
	readonly classLabels: readonly StoredClassLabel[];
	/** Index of the explicit positive label supplied for binary evaluations. */
	readonly positiveClassIndex: number | null;
	readonly partitionFingerprint: string;
	readonly partitions: readonly StoredPartition[];
	/** Pooled over every partition's test rows. */
	readonly pooled: {
		readonly test: StoredReport;
		readonly baselines: StoredPartition['baselines'];
	};
	readonly outputs: StoredOutputs;
	readonly curves: StoredCurves;
}
```

- T4 extends `ResultEnvelope` to a discriminated union. Version 1 keeps the Phase 3 shape. Version 2 includes required `evaluation: StoredEvaluation` alongside the same fitted artefacts and run identity. V2 One-Shot keeps both retained-relative index arrays and uses `evaluation.partitions[0].test` as its holdout report. Remove the duplicate legacy `holdout.report` from v2 only. V2 CV keeps the legacy fold, diagnostics and full-data refit fields. Both versions retain the existing identity checks. The startup reconciler restores a matching v1 result as trained with its existing identity, duration and log. Missing, malformed or mismatched envelopes continue to use the Phase 3 result-loss recovery, reopening Training Setup with the saved configuration. A storage access failure continues through the existing recovery path.
- `decodeStoredEvaluation(value: unknown): StoredEvaluation | null` (`src/features/results/evaluation-decoder.ts`) returns null for malformed shapes, unknown versions, invalid tags, class counts outside 2–65,535, invalid or duplicate labels, invalid partition order/count, wrong typed-array types or lengths, duplicate or unsorted original row indices, out-of-axis indices, inconsistent probability/source and score/source pairs, impossible metric or count values, a fingerprint outside 64 lowercase hex characters or calibration null means outside empty bins. Require binary positive index 1 and multiclass null. Validate array lengths against the declared axes and reports against partition counts. The v2 envelope validator additionally verifies evaluation axis, strategy and evaluated rows against the enclosing payload and its retained-to-original row map.
- `foldSummary(values: readonly number[]): { mean: number; sd: number | null; q1: number | null; median: number; q3: number | null; iqr: number | null }` (`src/common/evaluation/fold-statistics.ts`): `sd`, quartiles and `iqr` are `null` when `values.length < 2`; throws on an empty array or a non-finite value.
- `partitionFingerprint(input): Promise<string>` (`src/common/evaluation/partition-fingerprint.ts`) implements D4.
- `ModelRecord.metrics` on acknowledged success and startup reconciliation of a valid v2 result: `{ balancedAccuracy, accuracy, macroF1 }` from `pooled.test`, plus `balancedAccuracySd` from the held-out-fold presentation summary when partitions ≥ 2. Use the same projection for publication and reconciliation. A valid v1 result has `metrics: null`. Preserve Phase 3 clearing on training start and result-loss recovery.

- `setModelResultsUi(num: number, patch: Partial<ModelResultsUi>): void` writes `models[i].ui.results`; the persister drops an invalid `ui.results` (integer `0..100`, non-negative integer or null, boolean) to defaults without failing hydration.
- `$modelResults: MapStore<Record<number, ModelResultsResource>>` with `ModelResultsResource = { status: 'idle' | 'loading' | 'ready' | 'legacy' | 'lost' | 'error'; evaluation: StoredEvaluation | null; error: string }`. Each entry carries the full `TrainingRunIdentity`. Reuse an in-flight or terminal entry only when all six fields match and clear obsolete entries when the active dataset or model identity changes. Actions `loadModelResults(num)` and `retryModelResults(num)` read the envelope through Phase 3's `result-repository.ts` with the full run identity. A valid v1 result produces `legacy`; a valid v2 result produces `ready`. A missing, invalid or mismatched read for the still-current trained run produces `lost`; an access failure produces `error`. Discard a result if any captured identity field no longer matches the active record.
