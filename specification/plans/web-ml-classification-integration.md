# Integrate web-ml classification training and generated views

**Status:** draft | **Updated:** 2026-11-13T23:18:43Z

## Goal

**Current behaviour:** `package.json` installs `web-ml` from `file:../web-ml`, but `src/app.ts` renders placeholder model/results routes. `src/stores/app.store.ts` implements model lifecycle actions without a training service. `src/types/state.ts` contains provisional hyperparameter and validation types. `src/common/storage/indexeddb-dataset-provider.ts` reads whole datasets and can use whole-dataset statistics; it does not partition data for unbiased evaluation. `scripts/build-assets.ts` builds the app and ingestion worker but does not deploy the library's worker/WASM graph.

**Target behaviour:** Users train any of the eight supported binary or multiclass classifiers, configure controls generated from the library's JSON, optionally run Random Search, see accurate progress and useful failure messages, and reload persisted classification results. Results are arranged by validated, same-origin JSON layout documents. Numeric-target regression remains unavailable until a later release.

**Why:** Deliver an educational local training loop with meaningful control, enforce dataset separation, and establish bounded JSON contracts for both editable configuration and read-only results.

## Scope

**In scope**

- The eight classification model documents, their complete canonical single-label option inventory, a native-control renderer, and a small explicit presentation/validation policy for semantics absent from JSON.
- Manual training by default; opt-in Random Search with bounded budgets and an untouched test partition; multiclass behaviour supported by the chosen estimator.
- App-owned partitioning/preprocessing and evaluation in a dedicated integration worker; all estimator fitting, tuning, prediction and library scores use public `web-ml` APIs.
- Deployment of precompiled library assets, development/production isolation, cancellation, stale-run protection, local persistence and lost-result reconciliation.
- Single-model results and a small comparison table generated from a finite JSON layout vocabulary. Four unstyled structural drafts cover the missing later sections and comparison.
- Decisions for TODO-01, TODO-02 (initial classification subset), TODO-03 (table subset), TODO-04, TODO-05, TODO-21, TODO-33, TODO-50 and TODO-51; the preprocessing remainder of TODO-06 and later-mockup remainder of TODO-36.

**Out of scope**

- Regression, clustering, PCA pipelines, multilabel targets, arbitrary multiclass wrappers, ECOC, Hyperband, k-fold or nested-CV UI, automatic threshold tuning, fairness audits, decision boundaries, ROC curves, interactive charts, model export and inference on newly entered data.
- New optimisers, fitting algorithms or native compilation; modifications to `../web-ml` or installed package files. No Zig/Emscripten tooling here.
- A general JSON-to-DOM engine, arbitrary component/tag names or executable expressions in JSON, a new chart/form framework, Comlink, Storybook, or service-worker work.
- Reimplementing the setup, target or navigation plans. Their existing scope remains owned by them; this plan extends their delivered code.

**Constraints and invariants**

- Dataset contents, labels, predictions, model state and metrics never leave the browser. Server requests fetch static assets/configuration only. No telemetry is introduced.
- Strict TypeScript; Bun only; exported TypeScript has TSDoc. Native semantic controls, Baseline Widely available, WCAG 2.2 AA, British English and the existing locale infrastructure.
- Preserve dirty work already in the tree. Never commit, switch branches or rebuild the sibling library as part of this plan.
- The newest user instruction narrows the setup plan's earlier supervised catalogue to classification at integration time. Do not reinterpret a numeric column as categorical automatically. Numeric targets can remain selected by Step 2, but the models view explains that regression is coming later and offers a link to `/target`.
- Plans remain draft until explicit approval. Approval of this contract adopts the proposed TODO answers below; it does not approve deferred features.

### Interfaces and behaviour

#### A. Validated documents and deployment

`scripts/build-model-assets.ts` exports `buildModelAssets(outDir)`, returning a promise of `ModelAssetReport`, and is called by both build modes. Resolve package root from `import.meta.resolve('web-ml')`, verify it points at the installed built package, and read only there. Hash all copied runtime bytes plus the metadata/layout bytes; manifest URL `/models/index.json` has `{schemaVersion:1, revision:string, libraryVersion:string, runtimeUrl:string, models:[{id,taskType:'classification',specUrl,resultsUrl}], commonResultsUrl:string}`. URLs are root-absolute and confined to `/models/<revision>/` or `/vendor/web-ml/<revision>/`; no absolute third-party URL, traversal, query or fragment. Runtime sits at `/vendor/web-ml/<revision>/index.js` with the entire adjacent `*.js`/`wasm/` graph preserved, including licence notices. Package source, tests, node_modules and declaration files are never served. This includes unused runtime profiles if they form the shipped graph; offering their algorithms remains forbidden by the app allow-list.

Use build-time JSON imports via exported package subpaths or resolved package-root files; runtime fetches generated JSON, never sibling source URLs. Catalogue order comes from the library index. Assert exact id/file agreement, schemaVersion 1, unique IDs/option names, task type, references/defaults and the supported value-schema grammar. Use narrow handwritten runtime decoders, not a claimed complete Draft 2020-12 validator; a full JSON Schema engine is unnecessary for this closed subset. Fail the build for an unrecognised classifier option/schema/metric accessor, missing policy coverage, incompatible defaults or new classifier without a supported typed request branch. Non-classification entries are omitted rather than errors.

`src/features/models/model-documents.ts` exports `loadModelDocuments(signal?)` returning a promise of `ModelDocuments` and `loadModelDocument(id,signal?)` returning a promise of `ModelDocument`; `ModelDocuments` contains the validated manifest and catalogue. `ModelDocument` preserves all version-1 library fields. Cache successful immutable documents by revision, never failed requests; check response.ok, JSON content type, size (manifest 256 KiB, each document/layout 256 KiB) and parsed shapes. Check counts (64 models, 128 options/blocks per model, strings 8 KiB maximum), finite values and plain own properties. Reject prototype keys recursively. Unknown grammar fails closed with an inline error and Retry; never create guessed controls.

`model-catalogue.ts` from setup retains its synchronous selection API but filters to classification. The fetched documents must match that build's catalogue revision/IDs; configuration mismatches block Train and offer reload. This plan supersedes the earlier regression catalogue outcome in setup; it does not require removing existing article content or changing numeric column eligibility.

`src/features/models/model-presentation-policy.ts` keys rules by model ID and canonical option. It supplements rather than rewrites JSON defaults/types. Every option must be accounted for as editable/fixed/alias/inapplicable. The normaliser `normaliseModelOptions(document, overrides, context): NormalisedModelOptions` resolves prerequisite defaults recursively (cycle detection), applies structured defaultBy equality rules against effective values including omitted prerequisites, and returns `{effective, requestOptions, fields, issues}`. `overrides` contains only explicit user values. Fixed/conditional defaults remain effective display values without becoming accidental overrides. Reset removes a key; it does not write the currently displayed default. No-match conditional default means omitted with explanatory text. Preserve inactive overrides in state but omit them from requestOptions; show which are inactive. Treat appliesWhen/defaultNote as explanatory text only. No eval or expression parser.

Additional verified policy:

- All options numeric → finite. C>0; maxIter>=1 integer; l1Ratio/threshold in [0,1]; tol>=0 for Logistic/MLP but SVC tol>0; tree minSamplesSplit>=2, minSamplesLeaf>=1, maxDepth=null or integer>=1, minImpurityDecrease>=0; KNN nNeighbors integer>=1 and <= final/current training sample count, p>=1; NB alpha/varSmoothing>=0; SVC degree integer>=0, gamma>=0, coef0 any finite. App policy permits randomState integer 0–4294967295 (library JSON only says number); omission remains Random, with explicit reproducibility note.
- Adam learningRate is fixed 0.001, shown read-only; never offer a learning-rate search under Adam. L-BFGS/coordinate descent omit learningRate. L-BFGS supports penalties none/l2 only. C is active when penalty !=none; l1Ratio only elasticnet. Logistic threshold appears only for two classes; multiClass=ovr and multiLabel=false are fixed. SVC gamma only for non-linear kernels, degree only poly, coef0 only poly/sigmoid. KNN p only Minkowski. Invalid selections report issues and block Continue without silently changing another option.
- Native multiclass information is displayed from the explicit app capability map (Logistic ovr, SVC ovo, others native), not invented from JSON or an additional choice between unsupported wrappers. All eight support two or more classes. Store the compatible existing `multiclass` value via its action; never send that app value as an unrelated library option.
- Stable label order is the class codec's order in D. Priors/weights do not reorder when a form rerenders. Labels that collide under String conversion must be rejected before object-valued classWeight construction; do not map two labels to one key.

Search domains reuse those same native controls with a per-field Fixed/Tune choice. Enum/boolean → checked candidate list (nonempty, distinct values of correct types); bounded/integer/continuous scalar → integer/uniform/log-uniform with min/max numeric inputs. Inclusive numeric bounds require min<max, integers for integer domains, positive endpoints for log-uniform, and valid option bounds. Offer log-uniform only for positive continuous options. Fix solver, penalty, kernel, probability, metric, randomState and all structured/nullable options in v1; show why when appropriate. Tune only independent active scalar/enum/boolean fields whose entire domain passes the fixed context, including activation, criterion, weights, alpha/forceAlpha/fitPrior and relevant numeric options. Do not offer tuning singleton/fixed fields. At least one Tune domain is required in tuning mode. Keep baseOptions and searchSpace disjoint. Selecting tuning does not train immediately. Initial trials=10; 1–50 integer; seed=42 editable; objective=accuracy only in v1, labelled explicitly. F1/log-loss selection is deferred, although the library supports them. No thresholds are chosen using the test partition.

#### C. State, actions and migration

#### D. Preparation and unbiased evaluation

Create `src/features/models/training/prepare-classification.ts`; do not change the existing whole-dataset provider's default semantics. Read typed rows in 500-row pages from IndexedDB in the integration worker. Drop rows with missing target, report count, never impute target. Honour descriptor implicit-missing codes before fitting transformations. Eligible target is categorical/boolean only, at least two classes, at most 100 classes; each class needs at least three eligible rows in both modes so the same test split can be used for manual/tuning comparison. Explain the exact failing class/count, never fall back to unstratified splitting.

Codec uses observed typed labels, ordered by deterministic code-unit ordering of type prefix plus canonical value (no localeCompare). Preserve boolean/string identity and classLabels. Stratify with seeded Fisher–Yates using a documented deterministic uint32 PRNG (Mulberry32), seed mixed with the class ordinal. For each class of n rows, allocate test count clamp(floor(n*testRatio),1,n-2) from shuffled indices first; from the remainder allocate validation count clamp(floor(n*validationRatio),1,n-testCount-1). The rest train. Manual fits train+validation (development); tuning fits train and scores validation, freezes winner parameters, then explicitly calls ordinary train once on train+validation. The test rows are identical for equal dataset/target/seed/testRatio, independent of features and estimator. Persist row IDs/partition fingerprint in IndexedDB. No test scores influence candidate selection, preprocessing, hyperparameters or thresholds. Results explain that repeatedly comparing models on the same test set can bias later choices; nested CV remains a future stronger evaluation mode.

Fit numeric means on fitting rows only, and use them for missing numeric/boolean features when mean is selected; reject an all-missing fitting column. No metadata-wide means/medians or vocabularies may be used to fit. Categorical vocabulary is fitted on fitting rows, sorted deterministically; a reserved missing category is distinct from real category strings, unknown held-out categories encode all-zero. Each transformed feature name is persisted. Final refit fits a fresh transformer on development rows and applies it unchanged to test rows. Reject text/datetime features, non-finite outputs, duplicate/target features, or class-label collisions. MultinomialNB requires non-negative values across fitting and evaluated rows; reject negatives, never clip. Bernoulli binarize=null requires binary transformed values. Report incompatible data with column/row context. Numeric scaling is absent in this release.

Preflight width<=4096 transformed features, classes<=100, and estimated dense working memory<=128 MiB. Estimate at least eight dense matrix copies plus N×K probability storage, row IDs and model-specific MLP parameter arrays/KNN retained rows; use checked safe-integer arithmetic before allocation. This is a conservative app ceiling, not a guarantee of no OOM; library wasm-out-of-memory remains handled. Random Search uses maxWorkers=1 and memoryBudgetBytes=128 MiB to keep concurrency understandable. Counts and memory checks run before starting heavy work; show the selected row/column counts and excluded-target count in training summary. Changes to the ceiling require another explicit policy decision, not silent truncation.

Use public `BatchDatasetProvider` with fresh owned row-major Float64Array batches, targetCount=1, encoded targets and classLabels for every algorithm. Tuning uses a combined provider ordered train then validation, `trainingSampleCount`/`validationSampleCount`, `algorithm:'hyperparameter-tuning'`, `targetAlgorithm`, validated baseOptions/searchSpace/strategy/scoring. Use the unified train endpoint rather than the guide's mismatching provider examples for createTuner. Never assume buffers survive a transfer; regenerate batches for refit/evaluation.

Evaluate final predictions in chunks in the integration worker. Accumulate true/predicted labels for the complete test set and call library `accuracyScore` and `f1Score({average:'macro',labels})` once; never average per-chunk macro F1. For probabilities, call `logLoss(...,{labels})` per chunk and combine by sample-count weighting, then discard chunk probability buffers. Classifier adapters handle public prediction tensor versus label-array return shapes and probability column order explicitly. The app may aggregate a labelled K×K confusion count table; do not introduce fitting logic. Probabilities must be finite/nonnegative with positive row sums; logLoss uses the library's normalisation. SVC probability=false produces an explicit unavailable reason for log loss, not 0/NaN; it does not fail an otherwise valid result. The test matrix totals must equal evaluated row count. Do not call synchronous predict on the UI thread.

#### E. Worker, lifecycle, locks and progress

`src/features/models/training/protocol.ts` defines version-1 messages: page→worker `{version:1,type:'start',runId, snapshot}` or `{version:1,type:'abort',runId}`; worker→page `event` with original TrainingEvent and stage, preparation/evaluation counts, `result` with a validated portable ResultEnvelope, or `failed`/`cancelled`. snapshot contains datasetId, modelNum, classifierId, feature names, committed options, setup and descriptor identity, never live stores/functions. Validate both message directions, reject unknown versions/types and ignore mismatched run IDs. Worker imports no Lit/stores and dynamically imports only the manifest's verified runtime URL. One runtime library client is reused within that worker; no access to internal worker protocols.

Service assigns a random runId and immutable identity `{datasetId,modelNum,configurationRevision}`. Acquire app model Web Lock `samata-ml:training:{num}` before marking training; hold until persistence/terminal cleanup. This existing name is retained for reconciliation. Also hold shared `samata-ml:ingestion` during preparation/run/save to prevent same-origin ingestion from deleting rows; ingestion already uses that name exclusively. Acquire ingestion shared lock first, model exclusive lock second, using ifAvailable so a conflicting operation returns a visible busy reason without deadlocking. Library exclusively owns `web-ml:training` internally; never acquire it in the app. Once a model is training, duplicate starts are rejected; other documents can still queue different models through the library's origin coordinator. Lock loss/worker crash leads to a single terminal transition. Worker abortion must settle before replacement/discard is committed.

Integrate discard/target-change/dataset-replacement through the existing confirmation service boundary: abort this document's run, invalidate its token, delete affected model_results and await deletion before state discard. If a different tab owns the relevant model lock, show Training in another tab and disallow this mutation with a reason; do not reset its state or delete its active result. Every result save checks identity immediately before a short IDB transaction; late events/promises cannot revive a removed model. Storage events invalidate the local token and abort if dataset/model/configuration changed. Preserve normal navigation and scroll behaviour.

#### F. Result envelope and declarative layouts

`src/types/model-result.ts` defines ResultEnvelope schemaVersion=1 with datasetId/modelNum/runId, target column name, classifierId, libraryVersion, metadataRevision, configurationRevision, completedAt, classLabels, featureNames, requested/effective options, winning params when tuned, split seed/ratios/row IDs/testFingerprint, fitted preprocessing, serialised model state via public toJSON, common scores, confusion counts, declared diagnostics, optional trials, warnings and the timing fields above. All scores are finite numbers or `{unavailable:reasonCode}`; never NaN or undefined-as-zero. `model_results` remains keyed by dataset/model; no destructive DB version upgrade is required to type its existing value. Detailed rows/arrays/state remain in IndexedDB; localStorage holds accuracy/macroF1/available logLoss, short timings/identities and choices only. A mismatch between result identity and current choices means stale/lost results, never a stale success screen.

Persist via a result repository in `src/features/models/training/result-repository.ts` with `putModelResult(envelope)`, `getModelResult(datasetId,num)`, `deleteModelResults(datasetId,nums)`. The integration worker prepares/evaluates and returns the envelope; the service owns persistence and identity/lock checks using the repository. A failed save leaves the model draft with a storage error; it does not mark trained. Reconciliation validates envelope version/identity, not mere key existence. No library cacheKey is supplied. No optimiser checkpoint or per-row probability retention in v1.

Layouts are authored app JSON under `content/model-views/`, copied/versioned by the build. Root `{schemaVersion:1,taskType:'classification',blocks:ResultBlock[]}`; block has unique id, kind, labelKey and source (a finite app-defined data ID), optional allowlisted diagnosticId and unavailable policy ('omit'|'explain'). Kinds are `summary`, `scalar`, `number-array`, `confusion-table`, `history-table`, `trial-table`. No HTML, CSS, URLs, tag names, arbitrary object paths or expressions. Source IDs are `run-summary`, `accuracy`, `macro-f1`, `log-loss`, `confusion`, `trials`, plus model-diagnostic IDs validated against that model document. Schema/revision checks happen before rendering; JSON controls order and presence, code controls semantics/components. The build generates per-classifier diagnostic layouts from each document's metrics; initial common layout is the authored classification JSON. A compatible server layout rearranges blocks without renderer edits; unsupported kinds require a future code change and reject the document cleanly.

Safe diagnostic extraction uses an explicit adapter per classifier, never eval or unrestricted dotted lookup: MLP training-loss→`lossCurve_` (history-table), iterations→`nIter_` (scalar); tree node-count→`nodeCount_`, tree-depth→`maxDepth_` (scalar); KNN fit-sample-count→`nSamplesFit_` (scalar); SVC support-counts→`nSupport_` (number-array paired to fitted class order). Logistic/Gaussian/Multinomial/Bernoulli have empty metrics arrays: common test scores still display, and no synthetic diagnostics are claimed. An unknown accessor fails build validation; a declared but unavailable/non-finite runtime diagnostic shows an explanation and does not erase successful common scores. Loss history is a table, initially 50-row pages with First/Previous/Next/Last, persisted `model.ui.lossPage:number=0` via `setLossPage(num,page)`; no chart dependency. Trial table at most 50 rows. Support arrays and confusion matrix use semantic headers, never colour alone. Models with >20 classes offer a labelled true-class filter in results (all prediction columns remain accessible with horizontal scrolling); persist `model.ui.confusionClass:string|null` through `setConfusionClass`.

Comparison uses saved accuracy/macroF1/logLoss and actual library duration, model number/name/features/mode, with one row per trained model. No automatic winner ranking. Only records with identical datasetId/target/testFingerprint and label order can be directly compared; show incompatible rows separately with explanation, no pooled chart/averaging. `/results` still needs at least two trained records; compatible-group count<2 shows why no fair comparison is available. A missing/evicted envelope downgrades that model and recomputes eligibility; it cannot remain comparable just because localStorage says trained.
