## Goal

**Current behaviour:** This monolithic 16-task plan previously combined Step 3.3 manual hyperparameter controls, Step 3.3 hyperparameter tuning, Step 3.4 training setup, Step 3.5 worker training and progress, and Step 3.6 / Step 4 results into a single file.

**Target behaviour:** Superseded and split into seven sequential phase plans so each phase can be reviewed, verified, and implemented independently:

1. **Phase 1 (`ready-for-review`):** [web-ml-phase-1-configure-model.md](web-ml-phase-1-configure-model.md) — Step 3 (`3. Configure Model`) manual hyperparameter selection from `web-ml` JSON metadata and saving normalised values to application state matching `web-ml`'s `options` parameter (`Partial<TrainingOptionsFor<A>>`).
2. **Phase 2 (`draft`):** [web-ml-phase-2-training-setup.md](web-ml-phase-2-training-setup.md) — Step 4 (`4. Training Setup`) choosing between One-Shot Training and Nested Cross-Validation (with configurable number of folds), persisting `ValidationMethodology` to application state, and moving custom fold/split sizes to [FUTURE.md](../FUTURE.md).
3. **Phase 3 (`draft`):** [web-ml-phase-3-model-training.md](web-ml-phase-3-model-training.md) — Step 5 (`5. Train Model`) executing training via `web-ml`'s public functions with a single `<progress>` bar and an expandable `<details>`/`<summary>` message log.
4. **Phase 4 (`draft`):** [web-ml-phase-4-single-model-results.md](web-ml-phase-4-single-model-results.md) — Section 6 shared single-model metrics and visuals (balanced accuracy, baseline deltas, per-class errors, outer-fold spread, threshold explorer, calibration) and the persisted evaluation contract every later phase reads.
5. **Phase 5 (`draft`):** [web-ml-phase-5-model-comparison.md](web-ml-phase-5-model-comparison.md) — `/results` comparison of 2–8 models evaluated on identical rows (table lens, paired outer folds, per-class error profiles, Bayesian ROPE, instance agreement).
6. **Phase 6 (`draft`):** [web-ml-phase-6-model-specific-results.md](web-ml-phase-6-model-specific-results.md) — Section 6 model-specific internals for the eight classifiers.
7. **Phase 7 (`draft`):** [web-ml-phase-7-hyperparameter-tuning.md](web-ml-phase-7-hyperparameter-tuning.md) — Step 3 hyperparameter tuning configuration, tuned execution through Phases 2–3, and tuning results (trial history, inner-CV selection matrix, validation curves).

**Why:** Reduce plan size and cognitive load, isolate manual hyperparameter selection from hyperparameter tuning, and surface architectural contradictions between the requested phase boundaries and `web-ml@0.1.0`'s public API before implementation begins.

## Risks and open questions

- **Blocking:** This umbrella file is superseded by Phases 1–7 and is not directly implemented; status of the cross-phase items (`samata-ml` vs `web-ml`):
    1. **Nested Cross-Validation in Phase 2/3 vs Hyperparameter Tuning in Phase 7 (`web-ml` + `samata-ml`):** _Recommended & drafted for `web-ml`:_ Introduce `crossValidate(request, options?)` in `web-ml` for fixed-hyperparameter $k$-fold cross-validation (`mode === 'manual'` in Phase 3), keeping `nestedCrossValidate(request, options?)` strictly for outer+inner loop hyperparameter tuning (`mode === 'tuning'` in Phase 7). In Phase 2, the single "Number of folds" UI input maps to `outerFolds = innerFolds = folds` (`folds` in `crossValidate`). Upstream plan `cross-validation-refit-and-diagnostics.md` is `ready-for-review`.
    2. **Who runs evaluation folds (`web-ml` vs `samata-ml`):** _Resolved by the user on 2026-11-19:_ `web-ml` runs every fold (One-Shot evaluation, `crossValidate`, `nestedCrossValidate`) and returns per-row outputs, reports, baselines and curves (WR-1…WR-8, WR-10, WR-11). `samata-ml` never orchestrates folds or computes metrics. Consequence: Phases 3–7 depend on the ledger above.
    3. **One-Shot Training split ratio when fold/split sizes move to backlog (`samata-ml`):** _Resolved:_ fixed 80% train / 20% test stratified holdout (`testRatio: 0.2, randomState: 42`). Once WR-7/WR-10 land, Phase 3 uses `web-ml`'s split helper and pipeline so preprocessing is fitted on the 80% partition only.
    4. **State `HyperparameterValue` and JSON vs TypeScript/prose hyperparameter conflicts (`samata-ml` + `web-ml`):** _Resolved in `samata-ml`:_ Widen `HyperparameterValue` to include `null` and `Record<string, number>`, and apply `model-presentation-policy.ts` (`learningRate` editable under `sgd` and omitted under `adam`, `nIterations` hidden, `threshold` `0.5` and NB priors `Automatic` read-only).
    5. **Classification-only (8 models) vs all 14 supervised models & multi-modality catalogue design (`web-ml` + `samata-ml`):** _Resolved in `samata-ml` on 2026-11-19:_ Restrict `src/features/models/model-catalogue.ts` to the 8 classifiers in Phase 1 (updating `MOD-SETUP-4`) across Phases 1–7. Upstream `web-ml` task- and modality-scoped catalogue exports (`taskType` + `modality: 'tabular' | 'text' | 'image'`) remain an optional upstream enhancement.
    6. **Phase 7 tuning domain restriction on union types and `TrainingClient.train` narrowing (`web-ml`):** _Resolved:_ the refit plan verified with `tsc` that `HyperparameterDomain<T>` already accepts numeric ranges for `SVCOptions['gamma']`; Phase 7 uses the public, already-typed `createTuner().search()` (`TuningRun<A>` → `TuningResult<A>`) for One-Shot tuning and needs no `TrainingClient.train` overload.
    7. **Metrics, curves, baselines and the ROPE test (`web-ml`):** _Resolved by the user on 2026-11-19:_ all computed by `web-ml` (WR-3…WR-6, WR-9); Phases 4–5 wait for them.
    8. **Chart rendering (`samata-ml`, TODO-41):** _Resolved by the user on 2026-11-19:_ Observable Plot (`@observablehq/plot`), introduced in Phase 4; hand-built SVG charts move to [FUTURE.md](../FUTURE.md).
- **Non-blocking:** Draft mockups `03-4`..`03-7` and the new `04_compare-results` draft await human visual styling and promotion (`specification/HUMAN.md`).
