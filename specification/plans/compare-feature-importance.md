## Goal

**Current behaviour:** Compare Results (`/results`, `src/features/results/app-results-view.ts`) renders six comparison blocks before `<p>${t.noWinner}</p>` (`#L665-L820`; `chart-best-practices` gives each of those six `<section>` elements an ordered `<h2>` heading). No surface shows which inputs a model relies on. `StoredEvaluation` (`src/types/model-evaluation.ts#L113-L134`) is `schemaVersion: 1` and holds no feature-level data. `decodeStoredEvaluation` (`src/features/results/evaluation-decoder.ts#L454-L457`) rejects every other version, while `isTrainingResultPayload` and `decodeResultEnvelope` (`src/features/models/training/result-validation.ts#L395-L441`) and `decodeTrainingWorkerReply` (`src/features/models/training/protocol.ts#L156-L159`) discard the decoded evaluation and return raw stored payloads. The training worker (`src/features/models/training/training-worker.ts#L76,L95`) disposes each fitted model without inspecting it.

**Target behaviour:** During training, the worker measures **shuffle importance on held-out rows** for every cross-validation fold or the One-Shot holdout. Each fold model scores only its own held-out rows. The worker shuffles each raw column (all of its encoded columns together) and records how much **balanced accuracy** drops. The same shuffles are used for the same column, partition and repeat in every model. Immediately after the Instance agreement `</section>` and before `<p>${t.noWinner}</p>`, Compare Results adds a seventh ordered `<h2>` section, **Feature importance**, with:

- a **multi-model dot plot** (`COMPARISON_DOTS`), with one row per raw column and one dot per eligible model on a shared axis. Whiskers show variation across folds (or shuffle noise for One-Shot), and each model keeps its assigned `ModelColor`, numbered `.swatch` badge and marker symbol;
- a sort control (average importance, biggest disagreement, alphabetical), a "Show as share of each model's total (%)" toggle and "Show all N features", with `aria-live="polite"` status announcements;
- a skill gate: models that do not beat the most-frequent-class baseline (or have legacy/unavailable importance) remain visible in the legend with their exact status sentence and plot no dots;
- a visible marker and table note on columns where at least one pair of eligible models within `ROPE` ranks the column differently by at least three places;
- the "Computed on held-out data" label and the collapsible "What this does and does not tell you" note;
- a `<details>` data table inside `<figure>` that holds every value the chart shows across all rows for eligible models (omitted alongside `<figure>` when no selected model is eligible).

**Why:** VISION §9 asks learners to contrast inspectable models with an opaque network. Shuffle importance is the one measure that applies to all eight classifiers in the same units. The requirements note (`specification/notes/feature-importance-requirements.md`) makes `COMPARISON_DOTS` the default comparison view.

**Constraints and invariants**

- **Order:** `chart-best-practices.md` is currently `ready` and `virtual-table-improvements.md` is currently `draft` (`specification/plans/README.md#L49-L51`); neither has landed on `main` yet. Both vendoring the post-gate `web-ml` release and landing `chart-best-practices` (plus `virtual-table-improvements`, if still sequenced ahead) on `main` — followed by re-scouting `main` and the vendored release — block submitting this plan as `ready-for-review` (Risks: Blocking). Implementation lands before `web-ml-phase-6-model-specific-results` (`draft`, user decisions 2026-11-26).
- **I1 Held-out only:** importance is measured with the fold model (`kind: 'fold'`) on that fold's `validationFeatures`, or with the One-Shot model (`kind: 'holdout'`) on its `validationFeatures`. The refit (`kind: 'refit'`) is ignored. Each call asserts that `trainingIndices` and `validationIndices` are disjoint; if they overlap or `validationFeatures` is absent, the run's block becomes `null`.
- **I3 Raw columns:** every unit is one raw column, covering all encoded columns belonging to that raw source column (`JSON.parse(name)[0]` in `0.2.0` `tabular-preprocessing.md#L86-L89`, or `outputColumns` if `web-ml` ships v2 preprocessing metadata). Encoded columns are never shuffled independently.
- **I4 Metric and orientation:** balanced accuracy is used for every model. Importance is `baseline − permuted`, so positive means worse after shuffling. Negatives are never clamped in stored data; only `share` clamps.
- **I6 Determinism and pairing:**
  - let `k = context.kind === 'fold' ? context.foldIndex : 0` (so One-Shot `kind: 'holdout'` uses `k = 0`);
  - partition `k` uses `randomState = (IMPORTANCE_SEED ^ Math.imul(k + 1, 0x85ebca6b)) >>> 0`;
  - each unit's key is the unsigned 32-bit FNV-1a hash (`offset = 0x811c9dc5`, prime `0x01000193`, `>>> 0`) of its UTF-8 raw column name;
  - with `web-ml`'s keyed per-unit streams (`2026-11-26-grouped-permutation-importance.md` Q6), the same raw column, partition and repeat receive identical shuffles across models even when two models select different subsets or orders of columns. Comparison groups already guarantee identical partitions (`partitionFingerprint`).
- **Hook safety:**
  - `onModel` is awaited, and a thrown error fails training (`metrics.md#L99-L138`), so the collector wraps every step in `try / catch`;
  - it awaits `permutationImportance` before the hook settles (hook tensors are valid only until settlement);
  - it copies `importances` into fresh `new Float64Array(...)` buffers and never disposes the model or context tensors;
  - it forwards the worker's abort `signal`.
- **No partial blocks:** any failed partition marks the collector failed, sets `finish()` to `null`, emits `{ key: 'importance-unavailable' }` once, skips remaining partitions and lets training succeed.
- **Display arithmetic only:** `samata-ml` computes only the I5 summaries, shares, competition ranks, pairwise rank disagreement, the skill-gate comparison of stored partition scores and the axis domain (D5, D6).
- **Presentation rules:**
  - **Plain language:** say "shuffle" in default text, never "permutation" (rule 5).
  - **Spread wording:** label spread "variation across folds" (or "shuffle noise" for One-Shot), never "confidence interval" (rule 3).
  - **No hover-only information:** there are no Plot `tip` marks or hover-only tooltips; the `<details>` data table is the complete keyboard path (rule 10).
- **Post-`chart-best-practices` conventions** (`specification/charts.md`, `specification/components/results-comparison.md` §3):
  - Observable Plot (`@observablehq/plot@0.6.18`) only through `PlotController`;
  - `<figure>` wrapping `<figcaption>`, the chart container (`<svg role="img" aria-label="…" aria-describedby="…">` with internal `<g aria-hidden="true">` and `>= 12px` scaling text), and `<details>` data table;
  - Tier-2 presentational element with zero store/i18n imports and zero string literals, receiving typed `labels` with empty-string/empty-function defaults from `app-results-view`;
  - `ModelColor` identity via `modelSwatchStyles` numbered `.swatch` badges and `chart-encoding.ts` (`resolveModelMarkStyle`, `PLOT_SYMBOL_PATHS`, `computeAxisMargin`, `truncateLabel`);
  - closed `css/root.css` tokens only (zero literal colours or `var()` fallbacks), logical CSS properties, `>= 24×24 CSS px` interactive targets, `aria-live="polite"` control updates, WCAG 2.2 AA and British English.
- **Named constants** live in `src/config/feature-importance.ts` and are never inlined in components:
  - `TOP_N = 15`;
  - `REPEATS_DEFAULT = 5`;
  - `REPEATS_MIN = 3`;
  - `IMPORTANCE_SEED = 0`;
  - `IMPORTANCE_BUDGET_MS = 60_000` (pilot design choice);
  - `DISAGREEMENT_RANK_RANGE = 3`.

| Decision                                       | Chosen approach and rationale                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       | Rejected alternative / trade-off                                                                                                                          |
| ---------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D1 Measure                                     | `web-ml` `permutationImportance` with its post-gate balanced-accuracy scorer (pinned at re-scout), `nRepeats: REPEATS_DEFAULT`, the I6 partition seed and FNV-1a column keys, evaluated strictly on held-out rows. Balanced accuracy is the `/results` headline (I4; user decision 2026-11-26).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     | Accuracy now (rejected 2026-11-26); log loss (deferred).                                                                                                  |
| D2 Units                                       | One unit per raw column, derived **freshly per held-out partition** from that partition's own `preprocessing.featureNamesOut` (`JSON.parse(name)[0]`, or `outputColumns` if v2 metadata ships) with fold-local encoded indices ascending, because `TabularPreprocessor` fits per fold on `trainingIndices` and a rare category absent from one fold's training split legitimately omits that one-hot column on that fold. Partition 0 fixes the run's canonical `features` (in partition 0 first-appearance order) and unsigned 32-bit FNV-1a `groupKeys`. #### 1. Stored block, decoder and envelope validation

**Types** (`src/types/model-evaluation.ts`, exported with TSDoc):

```ts
/** One held-out partition's shuffle drops, in hook call order. */
export interface StoredImportancePartition {
	readonly nRepeats: number; // integer in [1, nRepeatsRequested] (D4)
	readonly baselineScore: number; // held-out balanced accuracy before shuffling, [0, 1]
	/** baseline − permuted per unit and repeat, `[u * nRepeats + r]`; may be negative. */
	readonly importances: Float64Array;
}

/** Held-out shuffle importance per raw column (schema version 2). */
export interface StoredFeatureImportance {
	readonly scoring: string; // web-ml balanced-accuracy scorer literal, pinned at re-scout
	readonly seed: number; // IMPORTANCE_SEED
	readonly nRepeatsRequested: number; // REPEATS_DEFAULT
	readonly features: readonly string[]; // raw column names, one per unit
	readonly partitions: readonly StoredImportancePartition[]; // CV folds in order, or one holdout
}
```

`StoredEvaluation` widens `readonly schemaVersion: 1 | 2` and adds `readonly featureImportance: StoredFeatureImportance | null`.

**Decoder rules** (`src/features/results/evaluation-decoder.ts`):

- `schemaVersion === 1` decodes with `featureImportance: null` and all existing fields unchanged.
- `schemaVersion === 2`: absent or `null` `featureImportance` decodes to `null`; otherwise a local helper validates: `scoring` is a non-empty string; `seed` is a safe integer; `nRepeatsRequested` is an integer `>= 1`; `features` is a non-empty array of unique non-empty strings; `partitions.length === evaluation.partitions.length`; each partition's `nRepeats` is an integer with `1 <= nRepeats <= nRepeatsRequested` (`nRepeats === 1` is valid, with `sd_r = 0` in D5); each `baselineScore` is finite in `[0, 1]`; each `importances` is a `Float64Array` of exact length `features.length * nRepeats` containing only finite numbers. Any failure catches its local `Invalid` and returns `featureImportance: null` while decoding the rest of the evaluation. `schemaVersion` values other than `1` or `2` return `null`.

**Normalised payload decoding** (`src/features/models/training/result-validation.ts` and `protocol.ts`):

- Export `decodeTrainingResultPayload(value: unknown): TrainingResultPayload | null` from `result-validation.ts`: runs the existing structural and `evaluationMatchesPayload` checks using `const evaluation = decodeStoredEvaluation(value.evaluation)` and returns `{ ...value, evaluation }` with the decoded `StoredEvaluation` (keep `isTrainingResultPayload(value): value is TrainingResultPayload` as `decodeTrainingResultPayload(value) !== null` for `training-worker.ts#L176`).
- Update `decodeResultEnvelope` (`result-validation.ts#L430-L441`) and `decodeTrainingWorkerReply` (`protocol.ts#L156-L159`) to use the `TrainingResultPayload` returned by `decodeTrainingResultPayload`, guaranteeing `evaluation.featureImportance` is `null` (never `undefined`) for version 1 envelopes and `null` (never a raw invalid object) when version 2 drops a corrupt block.

#### 2. Collector and Step 5 progress notes

**Collector** (`src/features/models/training/importance-collector.ts`):

```ts
export interface ImportanceCollectorDeps {
	readonly permutationImportance: typeof import('web-ml').permutationImportance;
	readonly prepared: Pick<PreparedClassification, 'targetCodes' | 'classLabels'>;
	readonly signal: AbortSignal;
	readonly now: () => number;
	readonly onNote: (note: TrainingLogMessage) => void;
}
export interface ImportanceCollector {
	readonly hook: FittedModelHook<Classifier>;
	finish(): StoredFeatureImportance | null;
}
export function createImportanceCollector(deps: ImportanceCollectorDeps): ImportanceCollector;
```

Per hook invocation:

1. If `context.kind === 'refit'`, return immediately. If `failed` is already true, return immediately.
2. Verify `context.preprocessing?.validationFeatures` is present and `trainingIndices` and `validationIndices` are disjoint (`Set` membership check). On failure, fail once (step 6).
3. Derive this partition's raw-column groups (`Map<string, number[]>`, mapping each non-empty raw column name to its strictly ascending encoded column indices) freshly from **this partition's own** `context.preprocessing.featureNamesOut` (or `outputColumns`; fail via step 6 if empty or malformed). On the first measured held-out partition (`partitions.length === 0`), fix canonical `features = Array.from(foldMap.keys())` in first-appearance order and canonical 32-bit FNV-1a `groupKeys` (D2), with `featureGroups = Array.from(foldMap.values())`. On subsequent CV folds (`partitions.length >= 1`), assert exact raw-column set equality (`foldMap.size === features.length && features.every((f) => foldMap.has(f))`, failing via step 6 if any raw column is missing or unexpected) and build `featureGroups = features.map((f) => foldMap.get(f)!)` ordered by canonical `features` alongside canonical `groupKeys`.
4. Build `validationTargets = Array.from(context.validationIndices, (i) => prepared.classLabels[prepared.targetCodes[i]])` and partition seed `randomState = (IMPORTANCE_SEED ^ Math.imul((context.kind === 'fold' ? context.foldIndex : 0) + 1, 0x85ebca6b)) >>> 0`.
5. If `!startNoteSent`, set `startNoteSent = true` and call `onNote({ key: 'importance-start' })` (emitted at most once per training run).
6. Run `permutationImportance` with `nRepeats` from D4, `classLabels: prepared.classLabels` and `signal` (measuring elapsed wall time via `now()`). Copy `importances` into a new `Float64Array`, verify length `features.length * nRepeats` and finite `baselineScore` in `[0, 1]` / finite drops. On any thrown error (other than an already-aborted `signal`, which sets `failed = true` quietly so cancellation settles cleanly) or contract mismatch, set `failed = true`, emit `onNote({ key: 'importance-unavailable' })` if not yet emitted, and resolve without throwing.

`finish()` returns `null` if `failed` is true or zero partitions were recorded.

**Progress mapper and log messages:**

- `TrainingLogMessage` (`src/types/model-result.ts#L27-L41`) adds `{ readonly key: 'importance-start' } | { readonly key: 'importance-unavailable' }`; `isTrainingLogMessage` (`src/features/models/training/result-validation.ts#L122-L149`) accepts both keys.
- `createTrainingProgressMapper` (`src/features/models/training/progress.ts`) adds a side-effect-free `note(message: TrainingLogMessage): TrainingUpdate` (`return { progress, note: message }`, identical to `warning()` at `progress.ts#L54-L58`), keeping `mapper`'s internal `progress` state untouched so concurrent `consumeEvents` (`training-worker.ts#L82-L107`) can never regress `stage` or emit duplicate phase milestones, while `applyTrainingSessionUpdate` (`training.store.ts#L91-L119`) appends the note in both initial `percent: null` and determinate `percent <= 85` states.
- `app-training-progress.ts` (`defaultLabels.formatEntry`) and `app-model-builder-view.ts` (`messages` + `formatTrainingLogEntry`) format English copy: `"Measuring feature importance on held-out rows…"` and `"Feature importance could not be measured for this run."` (`updateTrainingAnnouncement` announces the new entry once).

#### 3. View-model (`src/features/results/importance-comparison-view-model.ts`, pure)

```ts
export type ImportanceSort = 'average' | 'disagreement' | 'alphabetical';

export interface ImportanceCell {
	readonly meanImportance: number;
	readonly sdAcrossFolds: number | null;
	readonly monteCarloSe: number;
	readonly foldValues: readonly number[]; // v[k]
	readonly positiveFolds: number;
	readonly folds: number;
	readonly signal: 'consistent' | 'unclear' | 'negative';
	readonly share: number | null; // max(0, meanImportance) / Σ positive means within model; null if Σ === 0
	readonly rank: number | null; // 1-based competition rank ("1, 2, 2, 4") within model; null if ineligible
}

export interface ImportanceModel {
	readonly num: number;
	readonly label: string;
	readonly modelColor: ModelColor;
	readonly status: 'eligible' | 'below-baseline' | 'legacy' | 'unavailable';
	readonly hasPositiveShare: boolean; // true when status === 'eligible' and Σ positive means > 0
	readonly nRepeatsUsed: number | null; // min partition nRepeats when eligible, else null
	readonly nRepeatsRequested: number | null;
}

export interface ImportanceRow {
	readonly feature: string;
	readonly cells: readonly (ImportanceCell | null)[]; // aligned to models; null when model lacks feature or is not eligible
	readonly meanShare: number | null; // mean of non-null cell.share across eligible models with the feature; null if none
	readonly rankRange: number | null; // max − min cell.rank when >= 2 eligible models have the feature; else null
	readonly disagreement: boolean;
}

export interface ImportanceComparisonView {
	readonly evaluatedOn: 'outer-test-folds' | 'single-holdout';
	readonly models: readonly ImportanceModel[];
	readonly rows: readonly ImportanceRow[]; // union of features across eligible models, sorted
	readonly shownRowCount: number; // showAll ? rows.length : Math.min(TOP_N, rows.length)
	readonly xDomain: readonly [number, number] | null; // null when nothing can be plotted in the active mode
}

export function buildImportanceComparison(
	models: readonly ComparisonModel[],
	choices: { sort: ImportanceSort; share: boolean; showAll: boolean; ropeWidth: number }
): ImportanceComparisonView;
```

Exact rules:

- **`evaluatedOn`:** `models[0]?.evaluation.protocol.kind === 'one_shot' ? 'single-holdout' : 'outer-test-folds'` (reading `StoredEvaluation.protocol.kind: 'one_shot' | 'cross_validation'` from `src/types/model-evaluation.ts#L115-L121`; all models in a `ComparisonGroup` share one `partitionFingerprint` and protocol).
- **Competition rank:** within an `eligible` model `m`, `rank(m, f) = 1 + count(f' in m.features : meanImportance(m, f') > meanImportance(m, f))`.
- **Pairwise `disagreement` (2 to 8 models):** with `meanBalAcc(m) = mean_p(p.test.balancedAccuracy)`, `true` **if and only if** there exists **at least one pair `(A, B)` of `eligible` models** that **both** include `feature` (`cellA !== null && cellB !== null`), satisfy `Math.abs(meanBalAcc(A) - meanBalAcc(B)) < choices.ropeWidth` (both in `[0, 1]` fraction units), **and** satisfy `Math.abs(cellA.rank! - cellB.rank!) >= DISAGREEMENT_RANK_RANGE`.
- **Sorting (`rows`):**
  - `'average'`: `meanShare` descending, `null`s last, ties by code-point order (`a < b ? -1 : a > b ? 1 : 0`).
  - `'disagreement'`: `rankRange` descending, `null`s last, ties by `meanShare` descending (`null`s last), then code-point order.
  - `'alphabetical'`: locale-insensitive code-point order (`a < b ? -1 : a > b ? 1 : 0`).
- **Axis domain (`xDomain`) over `shownRows = choices.showAll ? rows : rows.slice(0, shownRowCount)`:**
  - **Drop mode (`choices.share === false`):** for every non-null `cell` in `shownRows`, let `w = evaluatedOn === 'single-holdout' ? cell.monteCarloSe : (cell.sdAcrossFolds ?? 0)`, `lower = cell.meanImportance - w`, `upper = cell.meanImportance + w`. If no non-null `cell` exists in `shownRows`, `xDomain = null`. Otherwise let `rawMin = Math.min(0, ...lowers)`, `rawMax = Math.max(0, ...uppers)`, `span = rawMax - rawMin`; if `span === 0`, `xDomain = [-0.01, 0.01]`, else `xDomain = [rawMin < 0 ? rawMin - 0.1 * span : 0, rawMax + 0.1 * span]`.
  - **Share mode (`choices.share === true`):** collect all non-null `cell.share` values in `shownRows`. If none exists (no eligible model, or every eligible model has `hasPositiveShare === false`), `xDomain = null`. Otherwise let `maxShare = Math.max(...shares)` and `xDomain = maxShare === 0 ? [0, 0.1] : [0, Math.min(1, maxShare * 1.1)]`.
