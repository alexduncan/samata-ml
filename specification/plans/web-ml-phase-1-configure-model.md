## Goal

**Current behaviour:** Section 3 of the model builder (`src/features/models/app-model-builder-view.ts` L1085–1091 via `renderPendingSection` L1008–1031) shows `<p class="pending-notice">Not available yet.</p>`. `src/features/models/model-catalogue.ts` (L1–18, L56) imports 16 `web-ml` model specifications and exposes 14 supervised models, including 6 regressors, although Phases 1–7 only implement classification. `HyperparameterValue` (`src/types/state.ts` L70) cannot hold `null`, which `maxDepth` and `binarize` need. The persister validates hyperparameters by shape only (`src/stores/persister.ts` L236–247, inside the unexported `validateAppState` L104–106) and never checks `modelId` against the catalogue. `handleReopenClick` (`app-model-builder-view.ts` L419–425) counts the reopened section itself as downstream for `configure-model`, so `Edit` on Section 3 would always open the confirmation dialog. `setHyperparameters` returns `true` for a no-op because `updateState` (`src/stores/app.store.ts` L104–118) returns `true` when the transform returns the unchanged state (L110–112). `/help/configure-model` is not a reserved route (`src/router/route-parser.ts` L36 matches only `/about`, `/privacy`, `/help`), so the help link in the draft would redirect to `resumePath`. The builder view declares no `i18n` messages; its strings are hard-coded.

**Target behaviour:** Section 1 lists only the 8 classifiers and shows a "No classification model available" notice linking to `/target` when the active target is numeric. Section 3 renders `3. Configure Model` with a `What do these settings mean?` help link that opens `content/en/pages/configure-model.md` in `<app-content-modal>`, and a form generated from `web-ml`'s model-specification JSON: a `Mode` select (Manual; Random Search disabled), native selects, checkboxes, synchronised range + number pairs (`linear`, `logarithmic`, `integer` scales), number inputs with Reset buttons, nullable/union mode selects and an MLP layer editor, each in the `.field` grid with a plain-English description, `<abbr title>` glossary terms and dependency notes. Every valid edit is saved to `model.hyperparameters.values` as sparse canonical overrides. `Save & Continue` validates, moves focus to the first invalid control if any, and otherwise completes the section, which then shows `3. Model Configured` with an `Edit` button. `normaliseModelOptions(...).requestOptions` yields exactly the active overrides, keyed and typed for `web-ml`'s `Partial<TrainingOptionsFor<A>>`, for Phase 3 to pass unchanged.

**Why:** Manual configuration is the first missing step of the classification workflow. Keeping it separate from training setup (Phase 2), training (Phase 3), results (Phases 4–6) and tuning (Phase 7) keeps the change small and bound to `web-ml`'s public `options` contract.

## Scope

**In scope**

- Restricting the catalogue to the 8 classifiers, the Section 1 numeric-target notice, and a startup rule that resets models whose persisted `modelId` is no longer in the catalogue.
- A typed view of the statically imported `web-ml` model documents, a presentation policy for every option of the 8 classifiers, framework-free scale and description-segment utilities, and the option normaliser.
- Widening `HyperparameterValue` with `null` and validating persisted values, without changing `STORAGE_VERSION`.
- The `/help/configure-model` reserved route and its English page.
- `src/styles/hyperparameters.styles.ts` (the `.field` family and scoped `input`/`select` rules), `.help-link`, and their story.
- `<app-model-configuration>` (Tier 2) wired into Section 3 of `<app-model-builder-view>`, with stories, unit tests and three-browser Playwright tests; updates to existing tests that assert Section 3 is pending.

**Out of scope**

- Regression configuration and training.
- Tuning (`mode: 'tuning'`, `tuningSearchSpace`): Phase 7. The `Random Search (advanced)` option renders `disabled`.
- Step 4 Training Setup (Phase 2), training execution (Phase 3), results (Phases 4–6).
- Logistic Regression `classWeight` (hidden until `web-ml` resolves the `current-limitations.md` L89–92 contradiction), custom per-class SVC `classWeight` maps (SVC exposes only `None` / `Balanced`), user-entered Naive Bayes `priors`/`classPrior` arrays and an editable Logistic Regression `threshold`: deferred until `web-ml` resolves the open upstream request below.
- The rules in `specification/notes/user-interface-principles.md` and the unclaimed sections of `specification/notes/user-experience-decisions.md` (Modified badges, Reset on every control, two-tier disclosure, auto-adjusting partners, Advanced section, browser compute caps). The user decided on 2026-11-19 that Phase 1 keeps the 03-4 draft design; a later plan claims the notes.
- `.field--folds`, `.field-visual`, `.fold-*` and their responsive rules in `hyperparameters.css`: Phase 2 owns them.
- Translating the builder view's existing hard-coded strings (only new Section 1 notice and Section 3 strings use `i18n`).
- Changing the `Configuration` column of the models table (`src/features/models/app-models-view.ts` L280–282), which keeps showing the persisted mode.

**Constraints and invariants**

- Strict TypeScript, Bun only, TSDoc on every exported symbol (`specification/standards-and-documentation.md`). British English in prose and UI strings.
- Native controls, Baseline Widely available features only, WCAG 2.2 AA (`specification/COMPONENTS.md` §1, §7). Every `id` referenced by `for`, `aria-labelledby` or `aria-describedby` lives in the same shadow root as the referencing element.
- No `unsafeHTML`, `innerHTML` or string-built markup (`COMPONENTS.md` §4); `<abbr>` comes from structured segments.
- Tier 2 elements import no stores and no `src/i18n.ts`; they take a typed `labels` object (`COMPONENTS.md` §2, §8). `src/common/` imports no Lit (`CONV-4`).
- File names pass `CONV-1` (one role suffix at most: `hyperparameters.stories.ts`, not `hyperparameters.styles.stories.ts`).
- Tokens from `css/root.css` only, no fallbacks, no literal colours (`COMPONENTS.md` §6.1, `tests/style-tokens.test.ts`).
- `requestOptions` never contains: an inactive option, Logistic Regression `classWeight`, `learningRate` unless the solver is `sgd`, `nIterations`, `threshold`, `multiClass`, `multiLabel`, `algorithm`, `priors`, `classPrior`, or any key absent from the model's `web-ml` options interface.
- Every `HyperparameterConfig` the form emits or the builder persists has no `undefined` entry in `values`: an option is removed by deleting its key, because `jsonEqual` (`app.store.ts` L36–61) compares key counts, so `{ a: undefined }` is not equal to `{}`.
- `STORAGE_VERSION` stays `1`: a lower or missing version resets all state (`persister.ts` `validateAppState` L104–106 and `readPersistedState` L374–414) and no migration exists, so a bump would wipe every user's dataset and models.
- `validateAppState` stays unexported; persisted-state tests go through `reconcileStartupState`, as `tests/state-and-storage.test.ts` L696–706 already does.
- Never read `../web-ml/src/**` or `specification/internals/**`; never modify `../web-ml`, `node_modules/`, `bun.lock`, or mockups outside `specification/mockups/ui-scaffold/drafts/`.

`getModelDocument` narrows `MODEL_DOCUMENTS[id]` against `schema.json` L26–185 and ignores unmodelled metadata fields (`description`, `defaultNote`, `enumDescriptions`, `example`, `appliesWhen`). Narrowing rules:

- Check for forbidden prototype keys (`__proto__`, `constructor`, `prototype`) on the document root, every hyperparameter object, every `valueSchema` object (recursively) and every `defaultBy[].when` object.
- Flatten `valueSchema` recursively over `oneOf` branches (throwing `ModelDocumentError` on any non-object branch, unknown `type`, or schema with neither `type` nor `enum`/`const`): collect `types` from string/array `type` fields plus the inferred primitive type (`'string' | 'number' | 'boolean' | 'null'`) of any `const` or `enum` values (deduplicated in encounter order); collect `enumValues` from `enum` arrays and `const` values across all branches (deduplicated in encounter order), or `null` when absent. (For example, SVC `gamma` yields `types: ['string', 'number']`, `enumValues: ['scale', 'auto']`; SVC `classWeight` yields `types: ['string', 'object', 'null']`, `enumValues: ['balanced']`; DT `maxDepth` yields `types: ['number', 'null']`, `enumValues: null`.)
- Validate `defaultKind`: `'fixed'` requires own property `default` (`defaultBy: null`); `'conditional'` requires a non-empty `defaultBy` array of `{ when, value }` plain objects where `when` is a non-empty plain object with scalar (`string | number | boolean | null`) values (`default: undefined`); `'data-derived' | 'random-if-omitted' | 'unspecified'` set `default: undefined` and `defaultBy: null`.
- Validate `aliasOf`: when present (non-empty string), `aliasPrecedence` must be `'primary-wins' | 'alias-wins'`; otherwise both are `null`.

```ts
// src/features/models/model-options.ts
export interface ModelOptionContext {
	readonly rowCount: number;
	readonly classCount: number;
}
export interface OptionIssue {
	readonly name: string;
	readonly messageKey: string;
}
export interface NormalisedModelOptions {
	readonly overrides: Readonly<Record<string, HyperparameterValue>>; // canonical, sparse, may include inactive
	readonly effective: Readonly<Record<string, HyperparameterValue | undefined>>; // defaults (incl. defaultBy) + overrides
	readonly requestOptions: Readonly<Record<string, HyperparameterValue>>; // active overrides only
	readonly issues: readonly OptionIssue[];
}
export function normaliseModelOptions(
	document: ModelDocument,
	values: Readonly<Record<string, HyperparameterValue>>,
	context: ModelOptionContext
): NormalisedModelOptions;
```

Rules (applied in this exact order):

1. **Canonicalise & filter:** Copy own keys of `values` while dropping unknown keys, `hidden` keys (including LR `classWeight`) and `fixed` keys. For any `alias` option, apply `option.aliasPrecedence` from the document (`'primary-wins'`: copy the alias value to the target only if the target is absent; `'alias-wins'`: overwrite the target), then delete the alias key. LR `nIterations` is `'alias-wins'` (`logistic-regression.json` L172, `hyperparameters.md` L130), so `{ nIterations: 300, maxIter: 500 }` becomes `{ maxIter: 300 }`. A numeric MLP `hiddenLayerSizes` value `n` becomes `[n]`.
2. **Unconditional effective values:** For every non-alias option with `defaultKind !== 'conditional'`, compute `effectiveDefault = option.defaultKind === 'fixed' ? option.default : undefined`, and set `effective[name] = Object.hasOwn(overrides, name) ? overrides[name] : effectiveDefault`.
3. **Conditional effective defaults (`defaultBy`):** For every non-alias option with `defaultKind === 'conditional'` (e.g. LR `learningRate` and `tol`), scan `option.defaultBy` in order and select the first rule where every `[depKey, expected]` entry in `rule.when` satisfies `effective[depKey] === expected`; its `rule.value` is `effectiveDefault` (or `undefined` when no rule matches, e.g. LR `learningRate` under `lbfgs`). Set `effective[name] = Object.hasOwn(overrides, name) ? overrides[name] : effectiveDefault`.
4. **Sparse override pruning:** For every canonical option, if `Object.hasOwn(overrides, name)` and `effectiveDefault !== undefined` and `optionValueEqual(overrides[name], effectiveDefault)`, delete `overrides[name]`.
   `optionValueEqual(a: HyperparameterValue | undefined, b: unknown): boolean` is a module-private helper in `model-options.ts` (`jsonEqual` is private to `app.store.ts` L36–61 and T2 must not touch `src/stores/`): `===` for primitives (so `null`, `false`, `0` and absence stay distinct), element-wise `===` with equal length for `number[]`, and `false` for every other pairing.
5. **Active filtering, validation & cross-option checks:** Evaluate `policy.activeWhen(effective)` against the resolved `effective` map. For each active option, validate `effective[name]` against the table domain and `context` whenever it is not `undefined`, whether it comes from an override or a default: an invalid value records one `OptionIssue` (for a default, e.g. KNN `nNeighbors: 5` with `rowCount: 3`, the message key is the same domain message the override would get); a valid active **override** is emitted into `requestOptions`; defaults are never emitted. Inactive overrides stay in `overrides` and never enter `requestOptions` or `issues`. Finally run the D7 cross-option check (`solver === 'lbfgs'` with `penalty === 'l1' | 'elasticnet'` adds an issue on `solver`). `null`, `false`, `0` and absence stay distinct throughout.

- **Compound fields** (`nullable-mode`, `gamma-mode`, `class-weight`): the visible `<label class="field-name" for="{name}-mode">` names a native `<select id="{name}-mode">` whose `<option>` texts come from `choices`. When the value mode is selected (`limited`, `threshold`, `value`), a range + number pair (or, for `binarize`, a number + Reset) follows inside `<div class="field-controls" role="group" aria-labelledby="{name}-label">`; the range has `aria-label="{valueLabel}"` and the number input a visually hidden `<label>` `exactValue(valueLabel)`. The mode select and the value controls share the `{name}-help` / `{name}-error` description. Switching to the value mode sets the table's starting value (`maxDepth` 10, `gamma` 0.1, `binarize` 0); choosing any other mode stores that mode's value (`null`, `'scale'`, `'auto'` or `'balanced'`), pruned per D5. `class-weight` has no value control.
- **Layer editor** (`hiddenLayerSizes`): a `<fieldset>` whose `<legend>` is the option name, with one row per layer rendered with `repeat()` keyed by a private stable layer id list (kept in step with the array, so equal sizes do not share keys); each row is a `<label>` `layerSize(n)` + `<input type="number" min="1" step="1">` with the same `badInput` / edit-state handling as other number inputs, and a `removeLayer(n)` button rendered only while more than one layer exists (the list is never empty). `Add layer` appends a layer of 100 and moves focus to its input; removing a layer moves focus to the next row's input, or the previous one if it was last. No layer-count cap (Risks).
- **Synchronisation and `validity.badInput`:** Keep per-field numeric edit state in a private `@state` map: `{ status: 'bad-input' } | { status: 'empty' } | { status: 'text'; text: string }`.
    - Range `input` → canonical value via `fromSliderPosition`, clears any edit entry and error for that field, fires change.
    - Number `input` → check `target.validity.badInput` **first** (browsers sanitise malformed `<input type="number">` text like `-` or `1e` to `value === ''`):
        1. If `target.validity.badInput`: record `{ status: 'bad-input' }`, leave canonical value and slider unchanged, fire nothing.
        2. Else if `target.value.trim() === ''`: for `randomState`, clear the edit entry and error, remove `randomState` from overrides, and fire change; for all other numeric fields, record `{ status: 'empty' }`, leave canonical value unchanged, fire nothing.
        3. Else: record `{ status: 'text', text: target.value }`; parse with `parseNumberText(target.value)`; if valid for the option's domain, update canonical value + slider, clear any error, and fire change; if out-of-domain, leave canonical value unchanged and fire nothing.
    - Rendering `.value` on `<input type="number">` (and each layer-size input): bind `.value=${state?.status === 'bad-input' ? noChange : live(displayText)}`, importing `noChange` from `lit` and `live` from `lit/directives/live.js`. Never pass `nothing`: a property binding commits `nothing` as `undefined` (`node_modules/lit-html/development/lit-html.js` L1285), which the browser sanitises to `''` and so erases the malformed text. `noChange` leaves the DOM untouched while the field is `bad-input`; `live()` compares against the element's current `.value` rather than the last committed value, so after a `noChange` render a later canonical value is still written even if it equals what Lit last committed. `displayText` is `''` for `{ status: 'empty' }`, `text` for `{ status: 'text', text }` (preserving `"0.00"` or `"1e5"` without reformatting), and otherwise the formatted canonical effective value (or `''` for omitted `randomState`).
    - Number `blur` → if the field has `{ status: 'bad-input' }`, `{ status: 'empty' }` (required numeric field), or `{ status: 'text' }` failing domain validation, set `aria-invalid="true"`, render `${name}-error` and announce it via the polite live region; never rewrite a valid user value (no clamping or reformatting).
    - Reset → removes the override, clears the edit entry and error, and fires change; the next render's `live()` binding writes the default. When the default text is `''` (omitted `randomState`), `live()` sees the sanitised `.value === ''` as equal and would not write, so the Reset handler also assigns `input.value = ''` on that element directly to clear any `badInput` text. Switching `document` resets the edit-state and error maps.
    - Inactive fields: whenever an edit (or a new `value`) makes a field inactive (`activeWhen` false, so it is not rendered), delete that field's edit-state and error entries in the same update. Its canonical override is untouched (an invalid draft never reached it), and when the field becomes active again it renders its canonical effective value. Inactive fields therefore never block Save, never receive focus and never appear in the live region.
    - Hidden value controls inside an active field follow the same rule: when a compound field's mode select leaves its value mode (`maxDepth` → Unlimited, `gamma` → Scale or Auto, `binarize` → Disabled), delete the edit-state and error entries of its number input in the same update, so returning to the value mode renders the starting value through `live()` in both the range and the number. Layer-size edit states are keyed by the row's stable layer id (not its index) and are deleted when that row is removed. Every edit-state and error map key therefore belongs to a control that is currently rendered.
- **Submit:** `<form novalidate>`; `Save & Continue` is `type="submit"` and disabled only when `this.disabled` is `true` (never for validation errors); on submit with issues (including issues on defaults, Interfaces B step 5) or invalid edit states, render all errors and focus the first invalid control in document order (in `updated()` after render); only rendered, active fields count. For an issue on a default, the error belongs to the field's number input (KNN `nNeighbors` shows its default 5 with the error). Retry/loading UI does not exist (D3).
