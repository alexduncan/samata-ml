## Goal

**Current behaviour:** `src/features/models/app-model-builder-view.ts` (L1092–1098) renders Section 4 (`4. Training Setup`) via `renderPendingSection` (L1008–1031) as `<p class="pending-notice">Not available yet.</p>`. `src/types/state.ts` (L80–83) defines provisional `ValidationMethodology` variants (`nested_cv`, `k_fold_cv`, `train_test_split`), and `src/stores/persister.ts` (L92, L257–267) checks only `trainingSetup.type` without validating numeric fields. `src/features/models/app-models-view.ts` (L285–287) renders the raw `model.trainingSetup.type` string. Reserved routes (`src/types/routes.ts` L5, `src/router/route-parser.ts` L36–38) hard-code individual help paths rather than supporting dynamic `/help/*` pages compiled from `content/{locale}/pages/*.md`.

**Target behaviour:** Section 4 lets a user configure One-Shot (a requested stratified 80% / 20% holdout, seed 42) or Cross-Validation (a single fold count, seed 42). The default is One-Shot. The fold controls show up to ten folds and a labelled partition diagram. Choices require current target statistics. **Train Model** saves the valid setup, completes Section 4, displays its summary with **Edit**, and opens the pending Section 5. The model stays a draft. Reloading or rolling back preserves the dataset. Both the builder and the models list show the same summary, and the form links to `/help/training-setup`.

**Why:** Give users a reproducible evaluation configuration they can inspect before training. Manual CV and future tuning share the selected outer-fold count. Phase 3 owns execution through the public library.

**Eligibility and summaries.** Use framework-free `src/features/models/training-setup.ts`. Keep the following exports and document each one.

- `computeTrainingSetupBounds(targetStats: ColumnStats | null): TrainingSetupBounds`, where `TrainingSetupBounds` is `{ readonly maxFolds: number; readonly minClassCount: number | null; readonly blocked: boolean }`. Unavailable stats return `{ maxFolds: 0, minClassCount: null, blocked: true }`. For a categorical target use the full category counts; for a boolean use true/false counts. Ignore zero-count classes, exclude missing targets, and require two observed classes and at least two labelled rows in each. Reject incompatible stats or negative, non-finite or fractional counts. Iterate once without spreading an unbounded category map into `Math.min`. For insufficient classes use `minClassCount: 0`; for a singleton minority use `1`. Both are blocked with `maxFolds: 0`. Invalid counts and unsupported types use `minClassCount: null`, `maxFolds: 0` and `blocked: true`. Otherwise return the smallest observed count `m`, `maxFolds = min(10, m)` and `blocked: false`.
- The two-row threshold is the UI’s minimum for configuring a holdout, including cases where 20% would round to fewer than one test row per class. Exact 80/20 feasibility, rounding and partition generation belong to the upstream splitter. The maximum above is the **manual CV** upper bound. The chosen `k` becomes `folds` for manual CV. For later equal-count nested CV the smallest outer-training class count must also satisfy `m − ceil(m / k) >= k`. For `m = 4, k = 4`, manual CV is eligible but each outer training fold has only three minority rows. With `m = 5, k = 4`, the lower bound is also three. With `m = 6, k = 4`, it is four. Phase 7 must revalidate at tuning entry. Phase 2 offers manual mode only and never assigns rows, simulates folds, or certifies a tuned run.
- `validateFoldCount(folds: number, maxFolds: number): FoldValidationError | null`. Use `'invalid-number'` for non-finite values and `'out-of-range'` for non-integers or values outside 2…maxFolds. `createCrossValidationSetup(folds: number)` constructs the CV variant after validation. The default count is `min(5, maxFolds)` only when the current target is eligible.
