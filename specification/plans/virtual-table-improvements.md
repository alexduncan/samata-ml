## Goal

**Current behaviour:** `src/components/ui-virtual-table.ts` scrolls inside its own `.table-viewport` (`overflow: auto`, `role="region"`, `tabindex="0"`, lines 70-78) over a segmented rail of 10,000 rows (`SEGMENT_SIZE`, line 43) with top/bottom spacers sized through `ref()` and `element.style.blockSize` (489-526). It renders rows with a Lit `html` map (497-519), overscans 5 rows, uses a 40px (2.5rem) re-measured row height, fixed 12rem columns and only `table-cell`/`placeholder-cell` classes. Header buttons show the raw column name. `src/features/data/app-dataset-preview.ts` renders a `.status-box` (358-381: error alert + Retry, "Loading rows…" status, "No rows to preview.") and a `section.controls-bar` (383-427: Previous/Next segment, Go to row, segment info) and a header with "Preview Dataset: {name}" and one default-style **Change Dataset** button. The table's offset is persisted as `regions['data-table']` (`app-data-view.ts:469-477`, restored by `restoreTableScroll` 209-218). Sample **Load Dataset** (`app-dataset-card.ts:105-106` → `app-data-view.ts:420-422` → `startDatasetLoad`, `src/stores/dataset.store.ts:326`) keeps the selection view until publication with no progress or error UI; sample errors only render inside the upload dialog. Uploads stay in `app-upload-dataset-dialog` until publication acknowledgement (`app-data-view.ts:399-407`) and the dialog bar likely jumps to full because parse-phase progress in `pipeline.ts` never advances `bytesProcessed` (it is first set to the byte length at typing, 482; `csv-stream.ts:66` is only `checkFileSize`). Descriptor `displayName` (`src/types/sample-dataset.ts:35-45`) is never shown. The Datasheet dialog is rendered only in selection mode (`app-data-view.ts:619-627`). `css/base.css:7-13` gives `<main>` `overflow-y: scroll`, making it the sticky scrollport despite navigation §8.1, so no route's `.page-header` actually sticks although `specification/components/page-header.md` §5 specifies sticky block-start zero (local sticky rules in six route views plus `src/styles/page-header.styles.ts:8-17`).

**Target behaviour:** The document scrolls the preview on both axes. The table body is a single rail whose block size is rows × measured row height; a recycled pool of absolutely positioned rows is moved with `transform: translateY()` from a `requestAnimationFrame` update decoupled from a passive `window` scroll listener, with one screen of overscan above and below. Columns get content-based widths from column statistics, type classes that set alignment, display names for sample datasets and a non-colour **Not used for training** marker on model-ineligible columns. Datasets taller than the browser-safe rail show the first N rows with a notice. The preview header reads "{name} Preview", offers **Datasheet** (samples only) and a red **Change Dataset**, and the column panel title shows the display name above the column name. **Load Dataset** switches straight to the preview with a labelled `<progress>` in main; uploads first validate the whole file in the Upload modal (pass 1, no writes), then close it and write to IndexedDB under the in-page progress bar (pass 2). Loading errors return to the selection view with an alert notification. The document scroll snapshot gains an inline offset and the `data-table` region is retired. Every route's page header sticks to the top of the viewport (static below a 30rem viewport height), and the document's scroll padding follows the measured header so keyboard focus is never hidden behind it.

**Why:** Implements the "Improve Virtualized Table" section of `specification/notes/ui-fixes.md` and the revised `specification/mockups/01-6_virtual-table.html` / `css/virtual-table.css` (commit `7a11581`), plus the `ui-fixes.md` item asking `header.page-header` to stick, with the maintainer's 2026-11-26 decisions (D1-D8 and D23 below) resolving WCAG, browser-limit and scope conflicts.

## Scope

**In scope**

- Ingestion: a validate-only worker pass (parse + profile + type election, no IndexedDB writes) and corrected byte/row progress reporting.
- Store: load stage and name in `DatasetLoadState`; two-pass upload orchestration; document `left` in `ScrollSnapshot`; removal of the `data-table` region writer.
- `ui-virtual-table` rewrite to document scrolling, rAF row recycling, row-limit cap, grid column tracks, typed cell classes, unsupported marker, display-name headers and a sticky offset custom property; Storybook stories.
- `.btn-red` button variant (style primitive).
- Sticky page headers on every route: removal of `main { overflow-y: scroll }`, a shared `StickyHeaderController`, document scroll padding and short-viewport unsticking (D23); removal of `main`'s `padding: 2rem`, with every child of `main` owning its own spacing (D28).
- Preview header, Datasheet entry point, row-limit notice, error/empty notifications, column builder with widths, sticky-offset measurement, short-viewport unsticking, document width for horizontal scrolling, column panel display name.
- In-page loading view (samples and upload pass 2), focus handling, selection-view error notification, upload dialog two-pass behaviour.
- Visual parity entries for the 01-6 mockup authorised by D2; updating the `01-8_table-loading.html` draft to the in-page loading structure; specification sync.

**Out of scope**

- Better date/time formatting, multiple-width presets and other `ui-fixes.md` open issues not listed above (e.g. "Format Dates & times better").
- A Cancel control during in-page loading (D5: none). Remote fetches stay non-abortable mid-stream.
- Sticky row headers, horizontal virtualisation, sorting/filtering.
- The `scroll-region-restoration.md` stub's merge/retry/cancellation work (it keeps the regions mechanism for the fold matrix).
- The modal scroll lock (separate `ui-fixes.md` item).

**Constraints and invariants**

- CSP `style-src-attr 'none'` (`public/_headers` line 2, `tests/csp-and-console.e2e.ts:176-187`): geometry only through CSSOM (`element.style.transform`, `.blockSize`, `.setProperty`); no template `style` attributes, no `styleMap` (`BETA-ERR-2`).
- `ui-virtual-table` stays Tier 2: no stores, workers, IndexedDB or `src/i18n.ts`; consumer-formatted strings only; cell text via `textContent` (markup renders literally).
- Navigation §8.1: the document is the only scroll container on the preview route; no ancestor of the table may have `overflow` other than `visible`.
- Previous dataset, target and models stay untouched until a new dataset publishes (state-and-storage §6). A reload during ingestion or validation lands on `'select'`; loading state is never persisted.
- WCAG 2.2 AA (COMPONENTS §7): header accessible names come from visible DOM text (no `aria-label`, no `title`); unsupported status is never colour-only; progress is labelled; focus is never lost when views swap; reflow at 320 CSS px and 400% zoom.
- WCAG 2.4.11: on every route, a focused element scrolled into view is never hidden behind a sticky page or table header (document `scroll-padding-block-start` follows the measured header).
- Tokens only from `css/root.css`; logical properties; motion inside `prefers-reduced-motion: no-preference`; British English strings.
- Sample ingestion contract, error codes and `INGESTION_PHASE_LABELS` (`src/features/data/ingestion/errors.ts:60-68`) are reused, not renamed.
- **Visual authority:** the maintainer authorised `specification/mockups/01-6_virtual-table.html` and `specification/mockups/css/virtual-table.css` at commit `8329a10` (still `status="draft"`) as the visual reference for this plan (D2); T4 is not blocked on promotion. If the human later edits or promotes 01-6, the implementer ports only what this plan names and records any further difference for the human.

```ts

	readonly contentChars?: number;
}
export interface VirtualTableWindow {
	readonly startIndex: number;
	readonly rows: readonly (readonly string[])[];
} // unchanged
export interface VirtualTableRange {
	readonly startIndex: number;
	readonly limit: number;
} // unchanged
export interface VirtualTableRowLimit {

}
export interface VirtualTableLabels {
```

- Events (host, `bubbles: false`, `composed: false`; the consumer listens on the element): `ui-virtual-table-range-change` (`VirtualTableRange`, deduplicated: only when the needed range is not covered by the last request), `ui-virtual-table-column-select` (`{ column: string }`), `ui-virtual-table-row-limit-change` (`VirtualTableRowLimit`).
- CSS custom property: `--ui-virtual-table-sticky-offset` (length, default `0px`). Internal `--_columns` is private.

Body: `div.table-body[role=rowgroup]` with `style.blockSize = renderedRows × rowHeight px`; rows `div.table-row[role=row][aria-rowindex=index+2]` absolutely positioned, `style.transform = translateY(index × rowHeight px)`; cells `div.table-cell[role=cell]` + type class + `.unsupported`, `title` = text; placeholder rows keep `placeholder-cell` and `aria-busy="true"`. **`observeStickyHeader` (framework-free, `src/common/sticky-header.ts`)** — `export function observeStickyHeader(header: Element, options?: { onBlockSize?: (px: number) => void }): () => void`. Starts a `ResizeObserver` (border-box) and a `matchMedia('(max-height: 30rem)')` listener, takes ownership of `--page-header-block-size` on `document.documentElement`, writes the effective size (0 while short) and calls `onBlockSize`; the returned dispose function stops both and resets the property to `0px` only if this observation is still the owner. No Lit import (CONV rules for `src/common/`).

**`StickyHeaderController` (shared reactive controller, `src/features/shell/sticky-header-controller.ts`, wraps `observeStickyHeader`)**

```ts
export class StickyHeaderController implements ReactiveController {
	constructor(
		host: ReactiveControllerHost & { readonly renderRoot: ParentNode },
		options?: { onBlockSize?: (px: number) => void }
	);
	hostConnected(): void; // subscribe to matchMedia('(max-height: 30rem)')
	hostUpdated(): void; // (re)observe the current .page-header in host.renderRoot
	hostDisconnected(): void; // disconnect, release ownership
}
```

One exported symbol; no events. Writes only `--page-header-block-size` on the root element and calls `onBlockSize` with the effective size in px. Does not query other elements' shadow roots.

**`selectDataViewMode` (framework-free, `src/features/data/data-view-mode.ts`)** — `export function selectDataViewMode(appState: Pick<AppState, 'dataset' | 'data'>, load: Pick<DatasetLoadState, 'stage' | 'errorStage'>): { mode: 'selection' | 'preview'; showLoadAlert: boolean }` per D20.

**`IngestionProgress` (internal)** — adds `columnsProcessed?: number; columnsTotal?: number`, populated only during `statistics`.

**Ingestion protocol (internal)** — request `{ type: 'validate'; requestId: string; source: IngestionSource }` → `result` value `{ rowCount: number; columnCount: number }`; `progress` and `error` as for `ingest`; `cancel` aborts it. Validation uses the single-active-request guard but not `INGESTION_LOCK` (it writes nothing). Client: `client.validate(source, { signal, onProgress })`.

**Edge rules**

- `totalRows = 0` → empty paragraph, no table. `totalRows > rowLimit` → notice above the table, `aria-rowcount = rowLimit + 1`, last reachable row `rowLimit − 1`.
- A late `window` for a range no longer pooled is ignored (no wrong-index population).
- Columns change → pool rebuilt; header re-rendered by Lit.
- Short viewport media change and page-header resize update the sticky offset and document scroll padding without re-render.
- Scrolling forwards, backwards and jumping keep `.table-row` children in ascending `aria-rowindex` order.
